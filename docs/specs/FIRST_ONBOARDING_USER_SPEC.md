# AI Notification Inbox — First Onboarding Development Guide

## 1. 온보딩 목적

첫 온보딩의 목적은 단순히 권한을 받는 것이 아니다.

사용자가 처음 2~3분 안에 다음을 이해하도록 해야 한다.

1. 이 앱은 모든 알림을 보여주는 앱이 아니다.
2. 아예 필요 없는 알림은 원래 앱/Android 설정에서 끄는 것이 좋다.
3. 일부는 필요하지만 일부는 필요 없는 앱은 AI가 선별할 수 있다.
4. 사용자는 자연어로 자신에게 중요한 알림 기준을 설명할 수 있다.
5. 시간, 앱, 대화방, 관계, 예외 조건까지 자연어로 설정할 수 있다.
6. 생성된 정책은 이후 직접 확인·수정·비활성화·삭제할 수 있다.

핵심 사용자 인식:

> “복잡한 알림 설정을 직접 만드는 게 아니라,
> 내가 원하는 걸 말하면 앱이 알아서 정리해주는구나.”

---

# 2. 온보딩 전체 흐름

초기 온보딩은 다음 5단계로 구성한다.

```text
1. 알림 접근 권한
2. 아예 필요 없는 앱 정리
3. 반드시 놓치고 싶지 않은 내용 설정
4. 추가로 보고 싶은 것 / 줄이고 싶은 것 설정
5. 고급 자연어 예시 + 최종 정책 확인
```

온보딩 완료 후 메인 Timeline으로 이동한다.

---

# 3. Step 1 — 알림 접근 권한

## 목표

사용자가 왜 Notification Access가 필요한지 이해하도록 한다.

## 화면 문구 예시

### 제목

**알림을 대신 정리하려면 접근 권한이 필요해요**

### 설명

> 이 앱은 휴대폰에 표시되는 알림 내용을 바탕으로
> 필요한 정보만 골라 정리합니다.

> 앱 내부의 대화나 데이터를 직접 읽지 않고,
> Android 알림에 표시된 정보만 사용합니다.

버튼:

```text
알림 접근 허용
```

권한 설정 화면으로 이동.

---

## 추가 안내

다음 내용을 짧게 표시한다.

> 분석하려는 앱의 알림과 메시지 미리보기가 켜져 있어야 합니다.

예:

```text
KakaoTalk 알림 OFF
→ AI 분석 불가

KakaoTalk 알림 ON
→ AI 분석 가능
```

---

# 4. Step 2 — 아예 필요 없는 앱 정리

## 목표

AI가 분석할 필요조차 없는 앱의 알림은 원천 차단하도록 유도한다.

이 단계는 AI 비용과 불필요한 데이터 처리량을 줄이는 데도 중요하다.

## 질문

> **아예 받을 필요가 없는 알림이 있나요?**

설명:

> 전혀 필요 없는 앱은 알림 자체를 끄는 것이 가장 깔끔합니다.
> 일부 알림만 필요한 앱은 AI가 골라드릴 수 있어요.

---

## 앱 목록

현재 알림을 발생시키는 앱을 표시한다.

예:

```text
KakaoTalk
WhatsApp
Gmail
Coupang
Instagram
은행 앱
뉴스 앱
날씨
ChatGPT
게임
```

각 앱마다 3가지 선택지를 제공한다.

```text
그대로 받기
AI가 골라주기
알림 끄기
```

---

## 예시

Coupang:

```text
AI가 골라주기
```

사용 이유:

> 배송은 필요하지만 할인광고는 필요 없음

게임 앱:

```text
알림 끄기
```

---

# 5. Step 3 — 반드시 놓치고 싶지 않은 것

## 목표

사용자의 기본 중요 정책을 만든다.

## 질문

> **어떤 내용은 꼭 놓치고 싶지 않나요?**

사용자가 선택할 수 있는 대표 항목을 제공한다.

MVP 추천 항목:

```text
약속 확정
일정 변경
돈 내야 하는 요청
입금 / 중요한 결제
답변이 필요한 메시지
내 이름이 언급된 메시지
가족 관련
업무 요청
예약 변경
배송 문제
보안 / 로그인
AI 작업 완료 / 입력 필요
```

다중 선택 가능.

---

## 자연어 입력

선택 항목 아래에 자연어 입력창 제공.

Placeholder:

> 원하는 기준을 편하게 말해보세요.

예:

> “돈 관련하고 약속, 내가 답해야 하는 건 꼭 알려줘.”

---

# 6. Step 4 — 추가로 보고 싶은 것 / 줄이고 싶은 것

이 단계는 두 영역으로 나눈다.

---

## A. 추가로 보고 싶은 것

질문:

> **급하지 않아도 정리해서 보고 싶은 게 있나요?**

예:

```text
특정 상품 할인
여행 관련
취미
특정 프로젝트
배송
뉴스
특정 사람의 메시지
특정 커뮤니티
AI 작업 결과
```

자연어 예:

> “기타 장비 할인은 광고라도 보여줘.”

> “제주 여행 관련 내용은 이번 주 동안 중요하게 봐줘.”

---

## B. 줄이고 싶은 것

질문:

> **반대로 줄이고 싶은 알림은 무엇인가요?**

추천 항목:

```text
쇼핑 광고
카드사 이벤트
뉴스 속보
SNS 좋아요/팔로우
단체방 잡담
게임 이벤트
일반 날씨 알림
반복 시스템 알림
프로모션
```

자연어 예:

> “광고는 숨기는데 배송은 보여줘.”

> “단톡방 잡담은 필요 없고 약속이 정해질 때만 알려줘.”

---

# 7. Step 5 — 자연어 고급 설정 안내

## 목적

사용자가 단순 체크박스 수준을 넘어 어느 정도 복잡한 조건까지 말할 수 있다는 사실을 이해하도록 한다.

제목:

> **이렇게 말해도 됩니다**

예시 카드를 5~8개 표시한다.

---

## 예시 1 — 시간 조건

> “밤 10시부터 아침 7시까지는 가족과 보안 알림만 알려줘.”

---

## 예시 2 — 특정 앱

> “쿠팡에서는 배송과 환불 관련 내용만 보여줘.”

---

## 예시 3 — 특정 대화방

> “이 단톡방에서는 약속 장소나 시간이 결정될 때만 알려줘.”

---

## 예시 4 — 답변 필요

> “내가 직접 질문받거나 내 답을 기다릴 때 알려줘.”

---

## 예시 5 — 업무 시간

> “업무시간에는 Slack과 회사 단톡의 일정 변경, 답변 요청만 알려줘.”

---

## 예시 6 — 주말

> “주말에는 업무 관련 알림을 조용히 처리해줘.”

---

## 예시 7 — AI Agent

> “Codex가 작업을 끝냈거나 내 입력을 기다릴 때 알려줘.”

---

## 예시 8 — 임시 관심사

> “이번 주만 여행과 항공편 관련 정보는 중요하게 봐줘.”

---

# 8. 정책 생성 Pipeline

온보딩에서 수집한 정보는 바로 직접 정책으로 저장하지 않는다.

다음 AI pipeline을 사용한다.

```text
사용자 선택
+
자연어 입력
+
기본 앱 상태
↓
OpenAI LLM
사용자의 전체 의도 정리
↓
Structured Policy JSON 생성
↓
코드 검증
↓
사용자 확인
↓
Policy 저장
```

OpenAI는 다음을 수행한다.

* 사용자의 선택과 자연어 통합
* 중복 조건 제거
* 상위/하위 조건 정리
* 예외 관계 정리
* 시간 조건 정리
* 앱별 조건 정리
* 최종 Policy JSON 생성

---

# 9. 초기 Policy JSON 구조

온보딩 결과는 최소 다음 형태로 저장한다.

```json
{
  "rules": [
    {
      "id": "rule_001",
      "enabled": true,
      "scope": {
        "apps": "ALL"
      },
      "conditions": [
        {
          "type": "MEETING_CONFIRMED"
        }
      ],
      "action": "SHOW"
    }
  ]
}
```

지원 요소:

```text
Scope
Condition
Action
Exception
Time Condition
Enabled
```

---

# 10. 최종 정책 확인 화면

온보딩 마지막에 반드시 현재 설정을 사람이 읽을 수 있는 형태로 보여준다.

예:

## 현재 알림 기준

### 항상 보여드림

```text
약속 확정
일정 변경
결제 / 회비 요청
답변 필요
가족 연락
보안 관련
```

### 조건부 표시

```text
기타 장비 할인
배송 정보
AI 작업 상태
```

### 조용히 처리

```text
일반 광고
단체방 잡담
SNS 반응
```

### 시간 조건

```text
22:00 ~ 07:00
가족 / 보안만 알림
```

# 11. 사용자 확인

버튼:

```text
이대로 시작
수정하기
```

하단 안내:

> 언제든 말로 바꾸거나 설정 화면에서 직접 수정할 수 있어요.

---

# 12. 정책 수정 가능성 안내

온보딩 완료 전 다음 메시지를 보여준다.

> **처음부터 완벽하게 설정할 필요는 없습니다.**

> 사용하면서
> “이건 앞으로 보여줘.”
> “이런 건 필요 없어.”
> “이 방에서는 약속만 알려줘.”
> 라고 언제든 바꿀 수 있습니다.

초기 설정에 대한 부담을 줄인다.

---

# 13. 기본 정책 원칙

사용자가 설정하지 않은 영역은 처음부터 공격적으로 숨기지 않는다.

MVP 기본값:

```text
UNKNOWN → SHOW
```

또는

```text
UNKNOWN → Timeline에 표시
```

중요한 정보를 놓치는 것을 최소화한다.

---

# 14. 온보딩에서 하지 않을 것

MVP 첫 온보딩에서 제외:

```text
복잡한 Custom Category Builder
Drag & Drop Rule Editor
세부 Probability Threshold 설정
고급 JSON 편집
Calendar 연동
Todo 연동
Wear OS 설정
AI Watch 상세 설정
```

AI Watch는 온보딩 이후 특정 대화방에서 별도로 활성화하도록 한다.

---

# 15. Progressive Disclosure 원칙

처음부터 모든 설정 옵션을 보여주지 않는다.

순서:

```text
간단한 선택
↓
자연어 입력
↓
정책 확인
↓
필요할 경우 상세 설정
```

사용자는 AI 시스템을 설정하는 것이 아니라 자신의 관심사를 설명한다고 느껴야 한다.

---

# 16. UX 핵심 원칙

온보딩은 기존 Android 설정 메뉴처럼 보여서는 안 된다.

사용자가 느껴야 할 경험:

> “어떤 알림을 받을지 하나하나 설정하는 게 아니라
> 내가 원하는 걸 AI에게 설명하고 있다.”

체크박스는 자연어 설정을 돕는 가이드 역할만 한다.

---

# 17. 화면 수 권장

MVP 온보딩은 5개 이내 권장.

```text
Screen 1
Notification Access

Screen 2
앱별 기본 처리

Screen 3
반드시 놓치고 싶지 않은 것

Screen 4
추가 관심 / 줄이고 싶은 것

Screen 5
고급 자연어 예시 + 최종 정책 확인
```

필요하면 Screen 4와 5를 분리하여 최대 6개까지 허용.

---

# 18. 온보딩 완료 조건

다음이 완료되면 onboarding 완료로 간주한다.

```text
Notification Access granted
+
최소 하나 이상의 사용자 Policy 생성
+
사용자가 최종 Policy 확인
```

이후 Main Timeline으로 이동한다.

---

# 19. 첫 사용 이후 학습

온보딩은 초기 설정일 뿐이다.

실제 사용 중 사용자가:

```text
중요함
필요 없음
이런 건 앞으로 알려줘
이런 건 숨겨줘
```

등의 피드백을 하면 Policy 수정 흐름으로 연결한다.

따라서 온보딩 정책과 이후 자연어 정책 수정은 같은 Policy Engine을 사용해야 한다.

---

# 20. 개발 우선순위

## Phase 1

온보딩 UI만 구현.

Mock policy 사용.

## Phase 2

현재 notification app 목록과 연결.

## Phase 3

OpenAI policy generation 연결.

## Phase 4

Policy preview 및 confirmation.

## Phase 5

실제 Policy Engine에 저장.

---

# 21. 최종 사용자 경험

사용자는 처음 앱을 실행하고:

```text
1. 알림 접근 허용
2. 필요 없는 앱 제거
3. 반드시 볼 정보 선택
4. 보고 싶은 것 / 보고 싶지 않은 것 설명
5. 복잡한 조건도 자연어로 설정 가능하다는 점 확인
6. AI가 만든 최종 정책 확인
```

이후 앱을 사용하면서 정책을 계속 자연스럽게 발전시킨다.

핵심 문장:

> **처음부터 규칙을 만들지 마세요.
> 무엇을 알고 싶은지만 말해주세요.**
