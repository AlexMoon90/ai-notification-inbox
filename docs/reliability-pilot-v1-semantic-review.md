# 파일럿 v1 지시 정리·질문의 사후 의미 검토

검토일: 2026-09-23. 독립 검토 담당 에이전트가 `dataset.json`의 최초 지시와 `settings.jsonl`의 40개 기록을 모두 비교했다. **모델 출력을 확인한 사후 질적 검토**이며 사전 고정된 자동 의미 점수나 사람의 독립 채점이 아니다. Jev 분류 결과·점수·응답 파일은 보지 않았다. 데이터·프롬프트·실행기는 변경하지 않았다.

## 범위와 관찰 수

- 40개 기록 모두 확인. 실제 출력은 ready 22 / needs_input 13 / unsupported 3 / 앱 검증 오류 2다.
- ready 기대 32개 중 9개는 재질문, 1개는 검증 오류로 최종 정리문이 없다. 비ready 기대 8개 중 7개는 기대 상태, 1개는 검증 오류다.
- 첫 질문 이후 사용자의 답변과 재정리 결과는 없다. 따라서 질문이 이후 올바르게 해결됐다고 판단하지 않는다.
- 아래 ‘위험’은 문장 차이의 해석상 위험이다. 실제 알림 누락을 관찰했다는 뜻이 아니며, Jev 결과에 맞추어 정답을 수정하지 않았다.

## 우선 해결할 의미 보존 문제

### 제외 범위를 넓힐 수 있는 한정어 누락

| 사례 | 원문 | 실제 정리문 | 위험 및 후속 검사 |
|---|---|---|---|
| pilot-017 | `changes only to the description` 제외 | `리마인더 및 설명 변경 알림은 제외한다` | ‘설명만 변경’을 ‘설명 변경’ 전체로 넓혔다. 시작 시간과 설명이 함께 바뀐 알림은 원래 알려야 하지만 정리문에서는 포함/제외가 충돌할 수 있다. |
| pilot-029 | `장소만 바뀐 것은 제외해` | `단순 리마인더 알림과 장소 변경 알림은 제외한다` | ‘만’이 사라졌다. 시간과 장소가 동시에 변경된 알림까지 제외할 위험이 있다. |
| pilot-015 | `Exclude routine tracking` | `배송 추적 ... 알림은 제외한다` | 일반 현황이라는 제한이 사라졌다. 배송 추적 업데이트에 실제 주문 문제와 사용자 행동 요청이 함께 있는 경계 사례가 필요하다. |

017·029의 핵심 문제는 정리문 안에 여전히 시작 시간 변경을 알린다는 문장이 있어도 해결되지 않는다. 두 조건이 동시에 맞을 때 우선순위를 사용자가 정하지 않았는데 새로운 충돌을 만들었다. 이번 고정 알림에 이 조합이 없더라도 문장 수준 결함으로 남긴다.

### 대상 관계·출처·고유명사의 정밀도 저하

| 사례 | 관찰 | 해석 |
|---|---|---|
| pilot-001 | `explicitly asks Alex` → `'Alex'라는 이름이 명시적으로 포함되고, 답변 요청 또는 의사결정을 요구` | Alex에게 하는 요청이라는 관계를 이름 등장과 요청 존재로 풀었다. 뒤의 ‘다른 사람에게만 요청 제외’는 남아 있어 완전 반전은 아니지만, Alex가 언급될 뿐 수신자 불명인 요청을 구분하는 반례가 필요하다. |
| pilot-005 | `a response from me` → `답변이 필요` | 누가 답해야 하는지 명시가 빠졌다. 한국어에서 사용자 본인이 생략됐다고 읽을 수도 있으므로 확정 오분류로 단정하지 않는다. 타인 회신 의무를 설명한 메일로 검사할 필요가 있다. |
| pilot-014 | `requiring me to pay tax` / `my tax payment` → `세금 납부 요청 또는 세금 납부 연체 알림` | 사용자의 납세 의무라는 관계가 명시적으로 남지 않았다. 타인의 납부 요청을 전달하는 메일과 구분 필요. |
| pilot-016 | `my pickup order` → `픽업 주문 준비 완료` | 사용자 주문이라는 소유 관계가 생략됐다. 타인 주문 상태를 알려주는 알림과 구분 필요. |
| pilot-019 | `invitation for me to interview` → `명시적인 면접 초대 내용` | 사용자 본인의 초대 조건이 약해졌다. 다른 후보자 면접 초대를 전달하는 메시지를 검사해야 한다. |
| pilot-022 | `내가 낼 관리비` → `관리비 관련 알림 중 미납 또는 ... 납부 요청` | 정리문에서 납부 주체가 생략됐다. 사용자에게 보여준 message에는 ‘사용자가 낼’이 남아 있어 UI 설명과 Jev 전달문이 다르다. |
| pilot-013 | `Chase notifications` → `Chase 관련 알림` | 출처 앱 제한을 관련 내용으로 읽을 수 있는 표현이다. 다른 앱이 보낸 Chase 관련 소식으로 확인할 필요가 있다. |
| pilot-007 | `Chicago Comets` → `시카고 코멧츠` | 원문 고유명사를 보존하지 않고 음역했다. 같은 대상을 의도한 것으로 보이나 이후 동일 개체 연결을 모델 추론에 맡긴다. 원문 이름 유지가 필요하다. |

일반 문장 번역과 고유명사 변경은 구분한다. Northbridge Rovers, Cedar Science, Harbor Music, Dana, 서울 운석, 달빛공방은 ready 정리문에 유지됐다. 채널명을 실제로 번역한 사례는 이번 ready 출력에서 발견하지 않았다.

## 명확한 입력에 대한 재질문 9건

| 사례 | 관찰 | 문제 |
|---|---|---|
| pilot-003 | 원문 `Robin, my name`인데 `Robin이 사용자의 이름이 맞습니까?` | 이미 제공한 사실 재질문. 작업 할당 의미 질문의 ‘이름 멘션’, ‘특정 키워드’ 선택지는 직접 할당과 동등하지 않아 잘못된 방향으로 유도할 수 있다. |
| pilot-011 | Maya가 보낸 DM이라는 명확한 요청에 `Maya의 이름이나 호칭` 요구 | 제공된 표시 이름을 다시 요구. 내부 계정 ID를 확보하지 못했다면 그 한계를 구분해서 물어야 한다. |
| pilot-020 | 비밀번호 변경 또는 새 로그인 요청에 같은 두 항목을 재선택하도록 요구 | 추가로 필요한 정보가 아니라 이미 선택한 의미를 다시 묻는다. |
| pilot-023 | `내 이름인 서윤`에 다시 사용자 이름 요구 | 확인된 사용자 정보 유지 실패. |
| pilot-026 | 재배송 날짜·수령 방법 선택 요청인데 두 조건을 다시 질문 | 이미 명확한 범위이며 ‘배송 실패 사실만’이라는 더 넓은 대안까지 제시한다. 아직 자동 반영한 것은 아니다. |
| pilot-027 | 발신자 표시 하린인데 정확한 이름을 다시 요구 | 의미 기반 회신 요청을 정확한 문구나 중요 플래그로 바꾸도록 유도한다. ‘특정 플래그(예: 중요 표시)’는 현재 입력에서 확보된 기능이 아니다. |
| pilot-028 | 계정 비밀번호 변경·새 기기 로그인을 요청했는데 계정 특정용 이름/호칭 요구 | 이름은 계정 식별자와 다르며, 원문은 알림이 내 계정이라고 명시한 경우다. 필요한 정보와 무관한 질문에 가깝다. |
| pilot-031 | 동의서 서명·제출 요청인데 같은 의미와 키워드 선택 요구 | 의미 판단을 키워드 포함 여부로 약화시킬 수 있다. |
| pilot-032 | Nori DM 요청에 Nori의 정확한 이름 재질문 | 이미 주어진 발신자 표시를 다시 요구한다. |

이는 ‘질문 수가 많다’만의 문제가 아니다. 알려준 내용을 잊고, 의미 조건을 키워드 조건으로 바꾸거나, 기존 범위를 더 넓은 선택지로 바꿀 수 있다. 아직 답변이 없으므로 동의 없는 대안 적용이 실행됐다고 주장하지 않는다.

## 남은 ready 11건과 검증 오류

pilot-002, 004, 006, 008, 009, 010, 012, 018, 024, 025, 030은 원문과 정리문 비교에서 뚜렷한 조건 변경을 발견하지 못했다. 이는 완전한 의미 동등성의 증명이나 알림 분류 통과 판정이 아니다. pilot-002는 정리문에는 수령 요청이 남았지만 change_summary는 ‘배송 실패 알림만’으로 줄여 사용자 확인용 설명이 덜 정확하다.

pilot-021은 `missing_options`로 result가 null이어서 실제 질문·정리문을 검토할 수 없다. 이를 모델 의미 오류로 특정하거나 내용상 통과로 계산하지 않는다. 037과 함께 검증 오류 2건으로 남긴다.

## 다음 개선·검증 제안

1. 의미 보존 체크 항목에 주체, 대상 관계, 출처 앱, 원문 고유명사, `only/만`, `routine/일반` 같은 제한어를 넣는다. 단순 단어 포함 검사를 통과했다고 완료 처리하지 않는다.
2. 이미 주어진 이름과 조건을 질문 상태에 확정 정보로 유지한다. 실제 부족 정보가 없으면 불필요한 재질문을 만들지 않는다.
3. 선택지 생성은 관찰 가능한 필드와 지원 기능에 연결한다. 지원되지 않는 조회수·구독·중요 플래그를 가능한 옵션처럼 표시하지 않는다.
4. 017·029의 동시 변경, 제3자 납부/회신/면접, 다른 앱의 Chase 언급 등 반례를 다음 버전 회귀 자료에 추가한다. 이번 고정 데이터는 바꾸지 않는다.
5. 사례에 맞춘 예외 문장 추가에 그치지 않고, 새 사례군과 다회차 답변 흐름으로 다시 검증한다. 이번 검토에서 얻은 사례는 이후 봉인 평가로 재사용하지 않는다.

이번 사후 검토에서 발견한 잠재적 의미 손실은 최종 알림 점수와 별도로 보존한다. 같은 12개 알림에서 결과가 같아도 시험에 없는 조건 조합의 의미 손실은 사라지지 않는다.
