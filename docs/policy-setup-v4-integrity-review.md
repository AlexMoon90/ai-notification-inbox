## v4 코드 정적 검토

`scripts/policy_setup_v4.py`는 v3의 세션·검증·전송을 재사용하고 별도 프롬프트/기능 계약을 전달한다. 원문과 실제 저장 답변, 질문 문구·선택 라벨을 포함하되 평가 정답을 전달하는 코드는 없다. v3 모듈 전역 프롬프트를 덮어쓰지 않는다.

현재 정책·답변·대화 선택이 없는 첫 입력이 ready이면 코드에서 normalized_instruction과 change_summary를 사용자 원문으로 보존한다. 이는 **해당 경로에서 불필요한 재작성의 손실을 피하는 방식**이며, LLM의 요약 정확도가 높아졌다는 증거로 계산하면 안 된다. 입력 자체가 완성됐는지와 지원 가능한지는 여전히 모델이 판단한다.

기존 정책 수정, 답변, 대화 선택이 있으면 모델이 병합한다. 대상·한정어·기존 조건 보존에 대한 의미 검사가 계속 필요하다. 대화 ID 유효성 검사는 텍스트 조건의 의미 검사와 별개다.

주의 사항: 원문 보존 경로에서도 `message`는 모델이 작성한 설명 그대로다. 원문을 보존한 normalized_instruction과 사용자에게 보여주는 message가 다른 의미인지 후속 검토해야 한다. 또한 원문 보존이 개인정보 마스킹을 대체하지 않으며 향후 외부 Jev 전달 경계에서도 필요한 마스킹이 적용돼야 한다. 이번은 합성 자료만 사용한다.

이번 10개는 작은 신규 개발 진단이며 제품의 다회차 신뢰도·앱 연동·Jev 정책 컴파일 통과를 의미하지 않는다.
