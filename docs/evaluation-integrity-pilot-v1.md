# 신뢰성 파일럿 v1 독립 검토

검토일: 2026-09-23. 현재 Phase 0 미완료 상태는 유지한다. 이 문서는 독립 합성 평가의 정답 품질과 해석 범위를 기록하며 제품 완료 판정이 아니다.

## 이번 실행에서 확인할 수 있는 것

- 40개 최초 지시에서 LLM의 첫 응답 상태를 기대 상태와 비교한다. 예상 구성은 ready 32개, 확인/대기/미지원 8개다.
- ready 기대 사례에서는 LLM 정리문과 검토된 gold_instruction을 각각 Jev에 전달하고 같은 12개 합성 알림의 분류 결과를 비교한다.
- 정상 완료 시 최대 32 × 12 × 2 = 768개 Jev 판단이다. 이 수를 768개 독립 알림이나 40개 설정의 전체 대화 완료로 표현하지 않는다.
- 적극 알림 기준은 0.8로 사전 고정하고, 0.5의 분류 결과는 별도 진단으로 보고한다. 점수를 본 뒤 임계값을 바꾸어 같은 평가의 성공으로 합치지 않는다.

## 해석 제한

1. Jev 실행 정책 JSON 컴파일러가 아직 없으므로 실제 아키텍처의 전체 경로 시험이 아니다. 앱 표시도 모의 결정이며 Galaxy 표시 성공을 의미하지 않는다.
2. 이번 실행은 첫 질문의 상태만 검사한다. 답변 반영, 조건 변경, 중단/재개, 사용자 동의, 최종 정책 활성화까지의 다회차 신뢰도를 입증하지 않는다. 기존 단위 시험은 실제 모델의 다회차 평가를 대체하지 않는다.
3. 상태 정답과 정리문 의미 정답은 다르다. ready가 맞더라도 범위·예외를 잘못 정리할 수 있다. 12개 알림의 판단이 같다는 것만으로 두 지시가 의미상 완전히 같다고 결론 내리지 않는다.
4. ready 기대 사례에서 모델이 질문하거나 API가 실패한 경우 원래 분모에서 제거하지 않는다. 상태 실패/미완료와 후속 판단 미실행을 함께 기록한다.
5. retain_for_review는 적극 알림 성공이 아니다. 적극 알림 누락과 삭제/숨김은 별도 지표다. 이번에 suppress를 실행하지 않는다고 누락이 0이라고 보고하지 않는다.
6. 영어 24개·한국어 12개·혼합 4개 및 각 도메인의 결과를 분리한다. 이 구성은 시장 대표 표본이 아니다. 합성 점수를 실사용 오류 확률로 환산하지 않는다.
7. 정답과 기대 상태, 알림의 기대 결과·근거는 제품 LLM/Jev 입력에서 제외한다. gold 경로는 원인 분리용이며 실제 LLM 경로 성공에 합치지 않는다.
8. 정답 검토자도 AI이며 작성자와 상관된 오류가 가능하다. 독립 역할 배정과 이견 검토는 도움이 되지만 사람 검증 또는 무오류 보장의 대체가 아니다.
9. 기존 prompt v3의 한국어 응답 지시를 유지한 기준 측정이다. 영어·혼합 입력 이해와 영어 사용자에게 자연스러운 질문을 제공하는 UX는 다르며 후자는 이번에 검증하지 않는다.

## 정답 검토·고정 기록

데이터 작성자와 다른 에이전트가 원문·알림·제안 라벨을 함께 읽고 검토했다. 라벨을 숨긴 독립 재채점은 아니며, 제안서의 완전한 블라인드 정답 검토를 완료했다고 주장하지 않는다. 모델 실행 전 검토 수정 사항을 반영하고 내용 해시로 고정한다. 고정 이후 정답 오류를 발견하면 원래 결과를 보존하고 수정 버전과 변경 이유를 별도 기록한다.

최종 구조 검사: 40개 지시, ready 32 / needs_input 4 / unsupported 3 / waiting 1, 영어 24 / 한국어 12 / 혼합 4, 12영역. ready마다 12알림이며 비ready는 0알림이다. 총 384알림 중 양성 160개, high_risk 표시 65개. 지시·알림 개수와 알림 ID 고유성 확인. ready 사례의 gold_instruction은 최초 지시와 동일하여 별도 정답 정리 과정의 임의 의미 추가는 없다.

검토 수정 완료:

- pilot-005-n06, pilot-027-n08: 요청받은 다른 사람의 이름만으로 사용자 본인이 아니라고 단정한 음성 라벨을 발견했다. 사용자에게 회신이 필요 없음을 알림에 명시했다.
- pilot-007, pilot-009: 다른 팀/채널을 다루는 본문에 목표 팀/채널 이름의 제목이 붙어 출처 해석이 모호할 수 있어 각각 Sports scores / YouTube activity로 중립화했다.
- pilot-037: 실행기가 빈 후보 목록을 전달하는 것을 확인했다. 기존 needs_input 정답을 앱 계약에 맞는 waiting으로 수정했다.

최종 파일 SHA256: `68565c1c5bd2e56762df3c3736abcf683c57174276d73a55da026fe7fe7588ff`. `evaluations/reliability-pilot-v1/review.sha256.txt`에 저장했다. 모델 실행 전에 정답을 고정했으며 이 검토 담당자는 API 호출을 하지 않았다.

실행기 정적 검토: OpenAI에는 instruction과 빈 후보만 전달하고 Jev에는 policy 및 app/title/text만 전달한다. 정답 라벨이 입력에 섞이지 않는 allowlist 구조, 전체 기대 분모 유지, gold/normalized 분리, 보류를 알림 성공으로 세지 않는 집계를 확인했다. pair의 gold 성공/normalized 실패는 정리 오류의 후보를 찾는 진단이며, 단일 호출의 모델 변동·언어 변화 영향을 배제한 인과 증명이 아니다.

구성 한계: 명확한 ready 지시가 80%이며 다중 턴·충돌·이전 정책 수정·대기 재개가 없다. 불확실한 알림의 gold를 강제하지 않기 위해 이번 분류 데이터는 명확한 양성/음성으로만 구성했다. 이 때문에 불확실성 처리를 검증하지 못한다. 모든 ready 사례에 같은 형태의 앱 변경과 본문 명령 삽입을 넣었으므로 이는 계획적으로 보강한 스트레스 검사이고 자연 발생 빈도가 아니다. 명백한 비대상 알림 일부는 앱별 실제 알림 형식과 거리가 있다. 실앱 캡처 재현성은 미검증이다.

검토 항목:

- 사용자 지시에 없는 범위 제한·기본값·예외를 gold_instruction에 추가하지 않았는가.
- 사용자 식별 정보, 대화/채널, 앱 지원 정보가 부족한데 ready로 처리하지 않았는가.
- 기대 결과가 알림에 실제로 제공한 필드로 판정 가능한가. 참여자 명단·전체 메일·미래 대화 등을 가정하지 않았는가.
- 양성/음성/불확실 사례의 근거가 구분되는가. 일부 알림 형식에 정답 힌트가 반복되지 않는가.
- ID, 스키마, 언어/도메인 수, 사례별 알림 수가 일치하는가.
