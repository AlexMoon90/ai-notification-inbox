# 정보 허브 구현·검증 기록 — 2026-09-27

기준: [사용자 수정안](INFORMATION_HUB_SCOPE.md). 이전 Timeline/하단 기준 메뉴보다 우선한다. 기존 전체 Phase 0 품질 게이트 완료를 뜻하지 않는다.

## 화면과 데이터

- 하단 Now / 메신저 / 분류함. Now 우측에서 기존 기준 관계도와 자연어 편집으로 진입한다. 일반 설정은 우측 설정 아이콘으로 접근한다.
- Now는 저장된 판정의 match + SHOW만 표시한다. 미판정/pending/review는 ‘확인할 알림’에서 접근하며 조용히 폐기하지 않는다. 전체 기록/기준 밖 필터를 Now 스트림에서 제거했다. 기준이 없는 초기 상태는 Now가 비어 있고 확인할 알림·메신저·분류함에서 기준을 만들 수 있다.
- 제목 → 최신 본문 → 작은 출처 아이콘/시간의 컴팩트 행. 확인된 이벤트만 작은 라벨로 표시한다. 의미 분류는 Now 표시 자격을 부여하지 않는다. 상태 없는 행은 라벨 공간이 없다.
- 메신저 서비스 탭은 실제 대화형 알림에서 생성한다. 현재 기본 문자 앱과 알려진 문자 패키지를 문자로 표시하며 원본 패키지는 유지한다. 서로 다른 문자 앱의 대화를 이름만으로 병합하지 않는다. 기존 기록은 수집 당시 없는 메타데이터를 추정해서 채우지 않는다.
- 대화 식별은 기존 shortcut 기반 ID → 단체방이 아닌 관측 person URI → 문자 발신번호 → 패키지/채널/Android 알림 키/방 제목의 보수적 fallback 순서다. 이름이 같아도 서로 다른 키는 합치지 않는다. 이로 인해 메타데이터가 약한 앱에서는 같은 대화가 나뉠 수 있다. 발신자를 단톡방 ID로 사용하지 않는다.
- MessagingStyle 배열은 내부적으로 시간 오름차순을 유지하되, 대화방 화면은 사용자 요청(2026-09-27)에 따라 최신 메시지부터 아래로 표시한다. 대화방 목록도 최근 메시지 순이다. 같은 방에서 timestamp/발신자/본문이 같은 반복 이력은 하나로 표시하며 최신 수집 원본을 참조한다. timestamp가 없는 항목은 임의 병합하지 않는다. 메시지 수는 ‘수집 N개’이며 실제 원래 앱의 미읽음 수로 주장하지 않는다. 대화 종류 입력 요구를 제거했다.
- 메시지/상세에서 기존 PendingIntent 열기와 원본 앱 fallback을 사용한다. PendingIntent는 메모리 참조이며 재시작 이후 정확한 방 이동을 보장하지 않는다. 임의 deep link를 만들지 않는다. 연락처 권한/전화번호부 조회·썸네일 저장은 추가하지 않았다.
- 분류함은 예약/배송/금융/쇼핑·주문/SNS/여행/기타. 목업을 사용자 실데이터 목록에 넣지 않는다. 과거 미분류 알림은 기타에 남고 자동 일괄 외부 전송하지 않는다.
- Room v2→v3은 기존 알림을 보존하고 메타데이터 컬럼과 hub_classifications를 추가한다. 분류 결과는 원본 snapshotId 외래키를 가지며 원본 삭제 시 cascade 삭제한다. 대화·메시지·Now는 원본 및 기존 정책 판정의 참조 투영이므로 원문을 화면마다 중복 저장하지 않는다.

## Jev 분류와 정책의 분리

typesafe-ai 스킬과 [Noul 문서](https://docs.typesafe.ai/primitives/noul), [API 계약](https://docs.typesafe.ai/api)을 적용했다. 모델은 기존 jev-1.13.0을 유지한다. 새 실시간 수신 알림만 별도 큐로 분류한다. 단순 분류에 OpenAI를 호출하지 않는다.

13개 유형을 독립 Noul로 판단해 여러 의미의 동시 연결을 허용한다. 생활정보 카테고리는 0.90 이상, 상태 강조는 0.95 이상일 때 채택한다. 이는 정책 숨김 임계값과 무관하다. 예: 항공 체크인은 예약+여행에 연결될 수 있다. 날짜·금액·장소를 생성하거나 구조화 필드로 확정하지 않는다. 원문 본문은 그대로 표시한다.

묶음 요약, 불완전한 긴 본문, 빈 알림은 의미를 추정하지 않는다. 요청 실패/큐 포화는 원본을 기타에 남긴다. 같은 원본은 DB 조회로 재호출하지 않고 동일 패키지/제목/본문/불완전 상태는 최근 100개 메모리 캐시를 재사용한다. 정책 판정과 의미 분류 호출 수·토큰·지연·예상 비용을 별도 purpose로 계측한다. 일일 차단 한도는 없다.

원문은 기존 로컬 Room에만 보관하며 분류 시 필요한 최신 제목/본문을 외부 API로 보낸다. 자체 서버 DB는 없다. API 제공자의 저장 정책을 앱이 보장한다고 표현하지 않는다. SQLCipher/Keystore DB 암호화는 이번에 구현하지 않았으며 현재 앱 sandbox와 백업 제외를 유지한다.

## 단계 상태와 제한

- 수정안 Phase 1~6: 코드 연결 및 로컬 회귀/네이티브 렌더 검사. 실제 Galaxy 탐색·기존 기기 DB 업그레이드는 연결 후 검증해야 한다. 기존 최근 500개 제한 대신 저장된 원본 전체를 조회한다. 대량 데이터 페이지 단위 조회는 후속 최적화다.
- Phase 7: 새 수신 분류 경로 구현, 데스크톱 실제 API 합성 검증. 최초 12개 중 6개 통과였고 질문 구체화/분류와 강조 임계값 분리 후 기본 12개 통과. 조정에 사용하지 않은 10개 중 8개 통과. 한국어 SNS 댓글(0.89), 간접 회의 제안의 답변 필요(0.67)는 누락되어 각각 기타/강조 없음으로 남는다. 이 두 실패를 숨기거나 기대값을 바꾸지 않았다. 분류 품질 게이트는 미완료다.
- Phase 8: 대화 문맥 추적·여러 메시지의 최종 결정 요약은 미구현. 앞 단계 품질/실기기 검증 전 진행하지 않는다. 현재 room ID와 메시지 원본 참조가 확장 지점이며 작동하지 않는 Watch 토글은 노출하지 않는다.
- 보관기간/고정/개별 읽음, 연락처 사진, 구조화 날짜·장소 추출은 미구현. 공유 원본은 모든 참조의 보관 필요가 없어질 때 삭제하도록 후속 설계해야 하며 이번 업데이트가 기존 기록을 삭제하지 않는다.

검증 자료: `evaluations/information-hub/`. 실제 알림 수신·다양한 OEM/문자 앱·메타데이터 부족 대화의 정확한 합치기는 아직 검증되지 않았다. 합성 분류 검사는 전체 사용자 조건의 정확도를 보장하지 않는다.

최종 로컬 검증: 단위 98개(실패/건너뜀 0), 빌드/lint 통과. Robolectric 네이티브 3화면 렌더 확인. DB v2→v3 원본 보존 및 외래키 cascade 검사 통과. Galaxy 연결 없음으로 설치/실기기 UI 검사 미실시. 준비된 HubDeviceTest를 연결 후 실행한다.
