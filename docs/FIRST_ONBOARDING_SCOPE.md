# 첫 온보딩 개발 범위

후속 앱 구현: [온보딩·공통 정책 연결 기록](STRUCTURED_POLICY_IMPLEMENTATION.md). 5단계 화면과 저장/재개, 실제 API 및 확인 후 저장을 연결했으며 검증 결과와 미지원 기능은 해당 기록을 따른다.

2026-09-24 [사용자 제공 가이드](specs/FIRST_ONBOARDING_USER_SPEC.md) 1~21절을 개발 범위에 포함한다. 첫 2~3분 안에 선택적 알림 정리, 자연어 기준, 이후 수정 가능성을 이해시키는 것이 목표다. 2~3분은 UX 목표이며 측정 완료 결과가 아니다. 이번 반영은 문서 작업이고 앱 구현·설치·Phase 완료를 뜻하지 않는다.

## 5단계 흐름

| 화면 | 내용과 조작 | 연결·완료 기준 |
|---|---|---|
| 1. 알림 접근 | 접근 목적, Android에 표시된 정보만 사용, 권한 설정 열기 | 복귀 시 실제 권한 재확인; 거절/중단 상태 보존 |
| 2. 앱별 기본 처리 | 최근 관찰된 알림 앱 목록, 그대로 받기 / AI가 골라주기 / 알림 끄기 | 실제 앱 식별자 사용; AI 선별과 OS 설정 이동을 구별 |
| 3. 반드시 볼 내용 | 대표 관심 항목 복수 선택 + 자연어 입력 | 선택과 자유 입력을 함께 보존; 모순 시 보충 질문 |
| 4. 추가 관심·줄일 내용 | 추가 관심 영역과 줄이고 싶은 영역, 선택 + 자연어 | 광고 속 관심 예외 및 ‘만/도’ 의미 보존 |
| 5. 예시·최종 확인 | 5~8개 고급 자연어 예시 카드, 생성된 정책 요약, 이대로 시작 / 수정하기 | 공통 검증·Diff·확인 통과 후 같은 Policy Engine에 저장, Timeline 이동 |

기본 5개 화면, 필요한 경우 4/5단계를 나눠 최대 6개까지 허용한다. 질문과 실제 대상 선택은 기존 공통 보완 컴포넌트를 활용하고 매번 별도 화면으로 늘리지 않는다. 상세 옵션은 필요한 순간에만 펼친다. 체크박스는 관심사를 설명하는 보조 수단이며 JSON 편집 UI를 노출하지 않는다.

## 권한·앱 상태·표현

권한 화면은 ‘알림을 대신 정리하려면 접근 권한이 필요해요’를 중심으로 설명한다. 앱 내부 대화/DB를 읽지 않으며 원래 앱 알림과 미리보기가 꺼져 있으면 분석에 필요한 내용을 받지 못할 수 있음을 알린다. 알림 ON만으로 전체 본문·과거 대화·참여자 정보가 보장된다고 표시하지 않는다. 긴 카카오톡과 불완전 미리보기는 기존 원본 확인 필요 처리를 유지한다.

앱 목록은 실제 관찰한 알림 앱을 근거로 한다. 신규 설치 직후 목록이 비어 있으면 그 이유와 새 알림 후 갱신 경로를 보여주고 관심 기준 입력은 계속할 수 있게 한다. 예시 앱 목록을 실사용 앱인 것처럼 생성하지 않는다. 마지막 수신 기록과 현재 권한/알림 설정을 혼동하지 않고 조회할 수 없는 상태는 확인되지 않음으로 표시한다.

- 그대로 받기: 해당 앱을 선별 없이 Inbox에서 보겠다는 선택으로 요약해 최종 정책에 반영한다. 원래 앱의 알림 설정을 켜거나 바꾸는 명령은 아니다. 다른 전역 숨김 요구와 겹치면 명시적 우선순위 또는 질문으로 정리한다.
- AI가 골라주기: 선택·자연어로 정한 기준을 적용할 대상으로 표시한다. 구체적 기준이 없는 상태에서 임의 HIDE를 만들지 않는다.
- 알림 끄기: 해당 앱/Android 알림 설정으로 안내해 사용자가 변경한다. 우리 앱이 다른 앱의 알림을 직접 끈 것으로 표시하지 않는다. 설정 복귀 시 확인 가능한 상태만 재확인하고, 확인 불가면 사용자 안내를 유지한다. 패키지별 설정 진입과 복귀 동작은 Galaxy 실기기에서 검증한다. 이 선택을 Inbox HIDE로 몰래 치환하지 않는다.

알림 설정을 끄면 이후 해당 앱의 알림 내용을 수집·판단하지 못할 수 있다는 점을 선택 시 짧게 알린다. ‘필요 없는 앱 제거’는 앱 삭제가 아니라 알림 설정 정리다. 시스템 UI/android 알림은 기존 수집 제외 원칙을 유지하며 줄일 항목에 선택했어도 AI 호출을 추가하지 않는다.

## 선택과 자연어 통합

Step 3 대표 항목: 약속 확정, 일정 변경, 납부 요청, 입금/중요 결제, 답변 필요, 이름 언급, 가족, 업무 요청, 예약 변경, 배송 문제, 보안/로그인, AI 작업 완료/입력 필요.

Step 4 추가 관심: 상품 할인, 여행, 취미, 프로젝트, 배송, 뉴스, 특정 사람/커뮤니티, AI 결과. 줄일 내용: 쇼핑/카드사 광고, 뉴스 속보, SNS 반응, 잡담, 게임, 일반 날씨, 반복 시스템, 프로모션.

선택되지 않은 항목을 숨김 의사로 해석하지 않는다. ‘가족’은 관계/실제 대상 확인이 필요하며 ‘내 이름’은 호칭 확인, ‘회사 단톡’은 실제 대화 선택, ‘돈 관련’은 조건 의미 보완으로 연결한다. 추천 선택과 자연어가 충돌하면 마지막 입력만 보고 조용히 덮어쓰지 않는다. 중복 제거는 범위·예외·시간·논리 조합이 같은 경우에만 적용한다.

예시 카드는 야간 가족/보안, 앱별 배송/환불, 특정 방 약속 결정, 답변 대기, 업무시간 Slack/회사 방, 주말 업무 QUIET, Codex 작업 완료/입력 필요, 이번 주 여행/항공편을 포함한다. 카드를 선택하면 편집 가능한 요청 초안으로 넣고 즉시 활성화하지 않는다. 아직 구현·검증하지 않은 조건은 지원된다고 약속하지 않으며 준비 중으로 구분한다.

## 시간 조건: 이번 요청으로 범위 확대

이전 기준 설정 문서에서 후속으로 두었던 시간/기간 조건을 이번 온보딩 목표에 포함한다. 지원·검증 전에는 시간 부분을 버리고 영구 기준으로 저장하지 않는다.

공통 Policy에 Time Condition을 추가하고 OpenAI 편집·strict schema·앱 validator·실행 엔진·Diff가 같은 계약을 사용한다. 계약 확정 시 다음을 포함한다.

- 일별 시간 구간과 자정을 넘는 구간(22:00~07:00), 주말/요일, 업무시간, 시작/종료 시각, 시간대.
- ‘업무시간’은 사용자가 확인한 값이 없으면 질문한다. ‘이번 주’는 기준 날짜·시간대·종료일을 명확한 날짜로 보여주고 확인한다. 여행 중 기기 시간대 변화 때 현지 시각을 따를지 고정 시간대를 따를지도 정의한다.
- 경계는 시작 포함/종료 제외로 명시하며 자정·주말·일광절약시간·재부팅·늦게 온 알림의 처리 기준을 검증한다. 시간 판단은 앱 코드가 담당하고 시각이 바뀔 때마다 LLM을 호출하지 않는다.
- 임시 관심사는 종료 후 그 임시 규칙만 적용 대상에서 빠져 기존 기본 정책이 다시 적용되게 한다. 그 사이 사용자가 수정한 다른 규칙을 과거 전체 스냅샷으로 덮어쓰지 않는다. 기간 밖 동작과 종료 시각을 미리 보여준다.
- 야간 ‘가족/보안만’에는 해당 시간·범위의 비일치 처리도 필요하다. 일반 앱 외부 알림음까지 끄는 기능으로 설명하지 않는다.

실제 스키마 필드·시간대 변경 정책·지연 수신 처리 기준은 정책 모델 A에서 확정하고 구현 전 검사표로 고정한다. 미정 상태의 조건은 미완성 초안으로 남긴다.

## 공통 정책 생성·검증

```text
온보딩 선택 + 자연어 + 확인 가능한 앱 상태 + 기존 정책/버전
→ OpenAI: 의도 통합·중복/예외/시간/앱 범위 정리, 정책 JSON 생성
→ strict schema + 결정론적 validator
→ 위험 변경이면 OpenAI semantic validator / 필요 시 보충 질문
→ 실제 저장할 JSON에서 사람이 읽는 정책과 Diff 생성
→ 사용자 확인 → 정책/온보딩 완료 상태 원자적 저장
→ Timeline
```

[AI 역할 결정](AI_ROLE_DECISION.md)과 [Policy JSON Validation](POLICY_JSON_VALIDATION.md)을 재사용한다. Jev는 온보딩 정책 생성·검증에 관여하지 않는다. 요청·기존 기준·필요한 실제 후보만 외부 AI에 전달하고 권한 부여를 모든 대화 내용의 무제한 전송 동의로 취급하지 않는다.

원문 rules/action 문자열 JSON은 개념 예시다. 온보딩 전용 실행 스키마를 따로 만들지 않고 [공통 정책 모델](POLICY_MODEL_SETTINGS_SCOPE.md)의 Scope / Condition / Action / Exception / Time Condition / Enabled로 정규화한다. 초기 생성에서도 넓은 HIDE·QUIET·WATCH, 새 예외 등 위험 기준을 동일 적용한다.

최종 확인은 항상 표시/조건부 표시/조용히/숨김/시간 조건을 실제 Action에 맞게 구분한다. ‘광고 숨김’을 ‘조용히’로 바꾸어 표시하지 않는다. ‘항상’에는 시간·예외·범위 제약이 있는 정책을 무조건 넣지 않는다. 현재 앱의 SHOW/QUIET 및 OS 통지 제어 한계도 사실대로 설명한다. 사용자 미설정 영역과 불확실한 알림은 Timeline에 표시한다. 정책 JSON의 미허용 값은 런타임 UNKNOWN과 달리 저장 거부한다.

‘처음부터 완벽하게 설정할 필요는 없습니다’, ‘언제든 말로 바꾸거나 설정에서 직접 수정할 수 있어요’를 제공한다. 이후 중요함/필요 없음/이런 건 알려줘 피드백은 같은 정책 수정·검증 흐름으로 연결하며 피드백 하나로 넓은 규칙을 무단 적용하지 않는다.

## 저장·재개와 완료

선택·입력·현재 단계·질문/답변·후보 참조·제안·검증 상태·base revision을 기기에 저장한다. 외부 설정 이동, 뒤로 가기, 앱 종료/재시작 후 복원한다. 편집이나 후보/권한 변경 후 오래된 검증/확인을 재사용하지 않는다. 중단 상태에서 기존 활성 정책을 덮어쓰지 않는다.

완료 조건은 실제 Notification Access 허용 + 검증되고 실행 가능한 사용자 정책 최소 1개 + 최종 사용자 확인 + 저장 성공이다. 미완성/Mock/저장 실패를 완료로 표시하지 않는다. 완료 직전에 권한과 버전을 재확인한다. 완료 후 권한이 회수되면 데이터는 보존하고 수집 중단 안내와 재설정 경로를 제공한다. 기존 사용자의 앱 업데이트로 온보딩을 강제 재실행하거나 기존 정책을 초기화하지 않는다. 재진입은 기존 정책을 바탕으로 한 수정안이다.

## 구현 순서 및 검증

원문의 Phase 1~5는 온보딩 내부 순서(OB1~OB5)이며 프로젝트 Phase 0~6 및 정책 A~F와 구별한다.

| 순서 | 작업 | 통과 기준 |
|---|---|---|
| OB1 | 5화면과 Mock 정책 | 단계 이동·뒤로가기·중단/복원·빈 목록, Mock 활성화 불가 |
| OB2 | 실제 수신 앱 목록·권한·설정 이동 | Galaxy에서 실제 앱 식별, 설정 복귀, 거절/취소/확인 불가 상태 |
| OB3 | OpenAI 통합 입력·시간 조건·공통 검증 | 선택/자연어 의미 보존, 위험 검증, 부족한 대상/시간 질문 |
| OB4 | 정책 미리보기·확인·수정 | JSON과 표시 일치, 예외/숨김/시간/무변경 구분, 오래된 확인 거부 |
| OB5 | 공통 엔진 저장·Timeline 연결 | 완료 조건, 원자적 저장, 재시작, 실제 선별·기간 종료 회귀 |

기존 권한 진입·기준 작성/초안·Timeline은 재사용 후보이지만 온보딩 전체 동작이 구현됐다는 뜻은 아니다. 공통 구조화 정책 엔진과 검증 파이프라인은 선행 의존성이다. AI Watch 상세 설정은 온보딩 이후 특정 대화에서 별도 활성화한다. custom category, drag/drop, 확률 설정, JSON 편집, Calendar/Todo/Wear OS는 첫 온보딩에서 제외한다.

검증에 빈 신규 설치, 권한 거절/회수, 앱 알림 OFF/미리보기 없음, 같은 이름의 다른 대화, 미지정 가족/본인 호칭, 광고+기타 장비 예외, 무선택 항목, 야간/주말/이번 주/시간대 변화, API 실패, 오래된 정책, 저장 실패, 기존 사용자 업데이트를 포함한다. 한국어/영어 입력과 영미권 주요 앱 시뮬레이션을 재사용한다. 완료 시간·질문 수·이탈/수정 비율·중요 알림 누락·호출/비용을 측정한다. 이번 문서 반영에서는 테스트를 실행하지 않았다.
