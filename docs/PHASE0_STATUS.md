# Phase 0 진행 및 검증 기록

현재 상태: Phase 0 구현, 빌드·자동 테스트 및 Galaxy 기본 수집 검증 완료. 실제 앱별 안정성 검증 대기. **Phase 0 완료 아님.**

## 구현

- Kotlin + Jetpack Compose Android 앱 (min SDK 26, compile/target SDK 36)
- 알림 접근 안내 및 시스템 설정 연결, 권한/리스너 연결 상태 표시
- NotificationListenerService → NotificationNormalizer → NotificationSink → Room
- 필수 알림 필드 및 MessagingStyle 메시지 저장, 앱 이름 조회 실패 시 packageName 대체
- 같은 키의 변경 이력 보존, 동일 스냅샷 중복 저장 방지
- 최근 500건 Inbox 및 필드 상세, 전체 저장 건수, 사용자 확인 후 기록 삭제
- 스냅샷별 contentIntent 실행, 연결이 없으면 명시적인 원래 앱 실행 안내
- 원문 로그 미출력, 백업 제외, 화면 캡처 보호, 인터넷 권한/AI 호출 없음

## 개발 환경과 초기 문제

- Mac의 Android SDK 및 Gradle 8.14 사용. 초기 JDK 17.0.7로 기본 빌드/테스트 통과 후, 추가 lint 중 JIT 내부 오류(assembler_aarch64.hpp)로 런타임 종료. 설치된 JDK 20.0.2로 전환하고 Gradle worker 2개/힙 2GB로 제한하여 재검증. 앱 바이트코드 타깃은 Java 17 유지.
- 첫 단위 테스트 컴파일 오류: StatusBarNotification 테스트 생성자와 UserHandle 사용을 수정
- lint가 메시지 읽기 API의 min SDK 불일치를 발견: AndroidX NotificationCompat 사용으로 수정
- 등록된 API 34 에뮬레이터는 시스템 이미지가 없어 실행 실패. 에뮬레이터 검증 성공으로 기록하지 않음
- 사용자 연결 Galaxy: SM-S911N, Android 16, One UI 속성값 80500
- USB 디버깅 및 알림 접근은 사용자가 직접 허용. APK 설치 및 실행 성공
- 알림 DB를 Mac으로 복사하는 검증은 자동 승인 검토에서 개인정보 노출 우려로 거절됨. 실행하지 않았으며, 대신 기기 안에서 건수와 합성 알림 존재 여부만 검사

## 카카오톡 기록 탭 오류 수정

사용자 보고: 알림 기록을 누르면 만료/열 수 없음 메시지만 표시됨.

코드에서 확인한 문제: Android 알림 키별 최신 스냅샷 하나만 이동 정보를 보관했고, 업데이트된 이전 기록 및 시스템 알림 제거 시 연결을 즉시 버렸다. 사용자 기기의 특정 클릭에 해당하는 실제 취소 사유는 원문을 가져오지 않아 단정하지 않는다.

수정:

- 스냅샷별 원래 PendingIntent를 메모리에 최대 500개 보관. 업데이트/알림 제거와 PendingIntent 취소를 구분
- 다른 스냅샷의 최신 토큰으로 임의 대체하지 않음
- 연결이 없거나 취소되면 명확한 안내와 ‘앱 열기’ 제공. 대화 직접 이동과 앱 실행을 구분
- 저장 기록 삭제/앱 화면에서 접근 권한 해제 확인 시 캐시 삭제
- 실행 가능한 앱의 조회에만 launcher intent query 사용, QUERY_ALL_PACKAGES 사용하지 않음
- 단위 회귀 검사: 이전 토큰 유지, 취소된 이전 토큰을 새 토큰으로 대체하지 않음, 캐시 한도 및 초기화
- Galaxy 회귀 검사: 연결이 없는 카카오톡 기록의 안내 창 → ‘앱 열기’ → 카카오톡 화면

변경 파일: InboxApplication.kt, InboxNotificationListener.kt, MainActivity.kt, NotificationData.kt, AndroidManifest.xml, NotificationCaptureTest.kt, GalaxyCaptureTest.kt, README.md 및 이 문서/수동 검증 문서.

수정 검증 결과(2026-09-21): clean debug 빌드 성공, 단위 테스트 8개 통과, lint 오류 0/경고 12. Galaxy에 수정본 설치 완료. 기기 회귀 테스트 `kakaoFallbackOffersExplicitAppLaunch` 통과(안내 창 표시 후 사용자가 누르는 ‘앱 열기’ 동작으로 카카오톡 실행 확인). 새 카카오톡 알림에서 정확한 대화방으로 직접 이동하는지는 별도 사용자 확인이 필요하다. 이미 사라진 과거 알림의 연결 정보를 복구했다고 주장하지 않는다.

### 사용자 확인 — 카카오톡 앱 열기

사용자가 ‘대화 바로가기를 사용할 수 없어요’ 안내 창이 표시되며, ‘앱 열기’를 선택하면 카카오톡이 정상 실행된다고 확인했다. 대체 앱 실행 경로는 사용자 확인 완료. 해당 기록의 직접 대화 이동은 실패/연결 정보 없음으로 유지한다. 새로 수신한 알림에서도 같은 안내가 나타나는지는 아직 확인하지 못했다. 과거 기록인지 새 알림인지 확인하기 전에는 카카오톡 전체의 직접 이동 기능이 정상 또는 불가능하다고 판정하지 않는다.

## 새 카카오톡 알림 탭 무반응 수정 — Android 실행 권한 전달

사용자 보고: 새 알림을 눌러도 화면 이동과 오류 안내가 모두 없음.

확인된 코드 결함: target SDK 36 앱이 PendingIntent.send()를 옵션 없이 호출했다. Android 14 이상에서는 보내는 앱의 화면 실행 권한 전달을 명시해야 하며, 누락 시 시스템이 예외 없이 화면 실행을 막을 수 있다. 기기 로그에서 과거 차단 사건을 특정하지는 못했으므로 사용자 클릭의 원인을 로그로 확정했다고 주장하지 않는다.

수정:

- Activity가 RESUMED인 사용자 클릭 경로에서만 알림 이동 실행
- Android 16 이상: MODE_BACKGROUND_ACTIVITY_START_ALLOW_IF_VISIBLE
- Android 14~15: MODE_BACKGROUND_ACTIVITY_START_ALLOWED (Activity 사용자 클릭 경로로 제한)
- Android 13 이하: 기존 동작 유지
- ActivityOptions를 PendingIntent.send에 전달. 토큰 취소 시 기존 명시적 앱 열기 안내 유지

검증(2026-09-21): debug 빌드 성공, 단위 테스트 9개 통과, lint 오류 0/경고 12. Galaxy에 수정본 설치. `freshKakaoPendingIntentOpensActivity` 기기 테스트 **통과(스킵 아님)**: 현재 카카오톡 알림의 저장된 스냅샷과 보관 중인 PendingIntent로 실행하여 카카오톡이 전면에 나타나는 것을 확인했다. 대체 ‘앱 열기’ 버튼은 사용하지 않았다. 특정 대화방/메시지의 정확한 위치까지는 개인정보를 읽지 않아 자동 검증하지 않았다.

변경 파일: InboxApplication.kt, MainActivity.kt, NotificationCaptureTest.kt, GalaxyCaptureTest.kt, docs/PHASE0_STATUS.md.

공식 근거: [Android PendingIntent sender opt-in 및 조용한 실행 차단](https://developer.android.com/guide/components/activities/secure-bal#senders-must-opt-in-for-pendingintent).

### 사용자 실기기 확인 — 카카오톡 대화방 직접 이동 성공

사용자가 수정본에서 새 카카오톡 알림을 누르면 해당 대화방으로 정상 연결된다고 확인했다. 따라서 Galaxy SM-S911N의 이번 검증에서 **새 카카오톡 알림 → 원래 대화방 직접 이동**은 사용자 확인 완료로 기록한다. 이는 ‘앱 열기’ 대체 경로와 별개다. 과거/취소된 알림, 다른 앱, 재부팅·절전 조건의 동작까지 검증된 것으로 확대하지 않는다. 최소 5개 실제 앱의 안정적 수집 등 나머지 Phase 0 완료 기준은 계속 미완료로 유지한다.
