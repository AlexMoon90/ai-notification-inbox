# OpenAI 지시 정리·재질문 구현 및 합성 평가

2026-09-22. 사용자 요청으로 Phase 0 앱과 분리한 Python 실험을 구현했다. OpenAI API 연결과 실제 합성 호출은 수행했지만 Android 앱 연결·Jev 정책 변환·실기기 UX 검증은 하지 않았다. Phase 0 및 Phase 2 완료를 뜻하지 않는다.

## 구현

- 자연어 지시, 기존 기준, 앱 기능/제한, 합성 대화 후보, 이전 질문/답변을 OpenAI에 전달한다.
- LLM이 단일/복수 선택·텍스트·대화 카드 선택 질문을 구성한다. 터미널에서 번호 또는 직접 입력으로 답하면 후속 질문/최종 지시를 생성한다.
- 실제 후보 ID/표시명과 사용자 선택을 검사한다. 없는 후보, 선택하지 않은 대상의 자동 연결, 선택 범위 누락, 미완성 최종 지시를 차단한다.
- 입력·답변·대기 상태를 로컬에 저장한다. 재실행 때 후보 파일 변경을 반영하고, 사라진 선택은 사용자 확인 후 해제/재선택한다.
- API 오류·거절·미완성 응답에서 초안을 보존하고 확정하지 않는다. 타임아웃은 45초이며 자동 재시도하지 않는다.
- 사용자 확인은 지시 초안만 확정한다. 활성 정책/OS 알림을 변경하는 코드는 없다.
- 호출 횟수·입력/출력/캐시 토큰·요청 바이트·latency·예상 비용을 기록한다. API 키는 환경변수 또는 승인된 로컬 파일에서만 읽는다.

## 확인한 흐름

- 명확한 지시: ‘모든 앱에서 광고는 조용히, 일정 변경은 알림’ → 추가 질문 없이 최종 초안.
- 회사 단톡 지정: 후보 카드 질문 → 사용자가 대화 A 선택 → 해당 ID를 유지한 ‘대화 A의 일정 변경만 알림’ 초안.
- 후보 없음: 대기 → 새 합성 후보 공급 → 카드 선택 → 초안 정리.
- 이름 누락: 이름 질문 → ‘지훈’ 답변 → 지훈을 명시한 최종 초안.
- 충돌: 카카오톡 전체 숨김과 이름 언급 알림의 우선순위 질문 → 사용자 답변 반영.
- 부분 변경: 회비 요청만 제외하면서 일정 변경 유지.

## 실패와 수정 기록

초기에는 모든 앱 범위에도 대화 선택을 요구하고 UI 종류에 맞지 않는 후보 참조를 만들었다. 프롬프트에 범위·지원 여부 판정 예시를 추가해 개선했다. 이후 ‘모든 앱’이라는 명확한 범위를 의미/이름도 확정된 것으로 오해하는 문제가 있어 각각 별도 확인하도록 보완했다.

검증기에도 문제가 있었다. 모델이 needs_input 상태와 유효한 질문을 반환했는데 중복 unresolved 목록이 비었다는 이유로 거부했다. 질문이 있는 needs_input은 그 자체로 미완성이므로 허용하고, 확인/적용 금지는 유지했다. waiting/unsupported에는 사유를 계속 요구한다. 해당 회귀 검사를 추가했다.

최종 남은 실패 3개:

1. `already_replied`: ‘내가 이미 답변한 요청 숨김’이 불가능하다고 설명했으나 상태를 unsupported 대신 waiting으로 반환했다. 기다리면 해결되는 것으로 표시할 위험.
2. `h_known_name`: ‘내 별명 달곰’이 명시됐는데 별명을 다시 질문했다. 사용자 입력을 보존하지만 불필요한 왕복 발생.
3. `h_membership`: ‘수진이가 참여한 모든 방 자동 조회’가 불가능하다고 설명하면서, 대안 수락을 기다리지 않고 방 선택 질문으로 전환했다. 후보를 ‘참여한 것으로 추정’한다고 표현한 것도 근거 부족.

이 실패를 통과로 간주하지 않는다. 최종 실행의 세 사례 모두 ready로 끝나지 않아 실행 정책으로 넘어가지는 않았다. 그러나 의미적 오류를 모두 앱 검증기가 차단한다고 주장할 수 없다.

## 해석과 제한

- 17/20은 상태·질문 종류·대상 참조·일부 핵심값에 대한 자동 판정이다. 알림 분류 정확도 85%라는 뜻이 아니다. Jev 분류·중요 알림 누락률은 이번에 측정하지 않았다.
- 별도 표현도 소규모 합성 데이터다. 처음부터 독립된 사용자 평가 데이터가 아니고, 검증기 수정 후 다시 사용했으므로 엄격한 미사용 최종 시험으로 보지 않는다.
- 통과한 최종 지시의 대상·이름·주요 변경 내용을 출력으로 점검했지만 전반적인 의미 보존/설명 문구는 독립 사용자 평가가 필요하다.
- 현재는 후보를 제한된 입력 목록으로 제공한다. LLM 도구 호출로 실제 DB를 조회하는 기능, 실제 후보 만료 스케줄러, Android 기준 목록, 서버 인증/배포, 정책 버전 동시 수정은 미구현이다.
- 전화번호·이메일·키 마스킹은 실험용 최소 처리이며 실제 개인정보나 실제 기기 알림 전송용으로 준비되지 않았다. 후보 표시명에 마스킹 대상이 포함되면 원본 이름 검증과 충돌할 수 있으므로 운영 시 불투명 ID와 로컬 표시명을 분리해야 한다.
- 기존 알림/대화 내용은 보내지 않았다. 확인한 API 연결은 로컬 실험에서의 연결이다. 휴대폰 앱은 여전히 OpenAI 미연결이다.
