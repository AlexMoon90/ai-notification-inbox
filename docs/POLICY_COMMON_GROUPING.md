# 공통 기준과 앱별 개별 조건 — 2026-09-24

## 표시 기준

공통 상황은 단순 이벤트 유형 목록이 아니라 실제 공통 처리 기준이다. 예를 들어 카카오톡의 광고 숨김과 문자의 광고 숨김은 조건·처리·적용 상태·시간·예외가 같으면 ‘광고 · 숨김’ 한 항목으로 묶고 해당 두 앱에 연결한다. 전체 앱 정책은 공통에 표시한다. 오른쪽 개별 지시사항에는 단일 앱 기준과 대화방/발신자/관계 등 세부 범위를 가진 기준을 표시한다.

공통이라는 표시는 ALL_APPS를 뜻하지 않는다. 선택한 앱 두 개의 합집합만 연결하며, 다른 앱으로 범위를 확대하지 않는다. 단일 앱을 눌러도 전체 정책에서 계산한 공통/개별 구분을 유지한다. 해당 앱과 무관한 발신자 예외는 표시하지 않는다.

기존에 독립 저장된 규칙은 ID와 원본을 유지한 채 화면에서만 묶는다. 공통 항목을 다시 누르면 앱별 원래 규칙의 설정하기를 선택할 수 있다. 공통 표시를 이유로 기존 규칙을 삭제하거나 활성 상태를 바꾸지 않는다. 다른 처리·꺼짐 상태·내용 한정·시간·예외는 같은 항목으로 합치지 않는다. 문자열 의미가 비슷하다는 이유로 추측해서 병합하지 않는다. 배열 순서까지 일치하는 보수적인 비교이며, 의미는 같아도 표현이 다른 기존 JSON은 별도로 남을 수 있다.

## 새 요청의 정책 편집

OpenAI 편집/검증 공통 계약에 다음을 추가했다.

- 같은 동작의 새 앱을 명시적으로 추가하면 기존 순수 앱 기준의 ID를 유지하고 `scope.apps`만 요청한 앱들의 합집합으로 확장한다. SPECIFIC_APP은 여러 앱을 담을 수 있다.
- 새 정책 작성에서도 같은 기준을 앱마다 복제하지 않는다. ALL_APPS로 바꾸지 않는다.
- 기존 별도 저장 ID의 임의 삭제/병합은 하지 않는다. 무관 기준·꺼짐 상태·시간·예외를 보존한다.
- 카카오톡 특정 발신자의 쇼핑 광고 허용은 앱+발신자가 모두 맞는 좁은 SHOW 기준으로 표현한다. 공통 광고 HIDE는 그대로 두고 런타임의 명시적 구체성 우선순위를 이용한다.
- 같은 범위의 내용 예외는 기존 부모의 nested exception을 사용한다. 현 예외 JSON에는 별도 scope가 없으므로 앱/발신자 제한을 가진 예외를 공통 부모 안에 잘못 넣지 않는다.
- 관찰되지 않은 발신자나 미확정 대화는 만들어내지 않고 보충 질문한다.

추가·변경은 기존 strict schema, 결정론적 검사, 위험 시 의미 검사, 변경 비교/사용자 확인 후 저장 경로를 그대로 사용한다. Jev 역할과 실제 알림 실행 엔진은 바꾸지 않는다.

## 검증 범위

결과는 `evaluations/policy-common-grouping/result.json`에 기록한다. 화면 그룹화가 원래 ID/범위를 보존하는지, 서로 다른 제한은 합치지 않는지, 발신자 허용이 다른 앱/발신자로 전파되지 않는지 검사한다. 실기기 테스트는 합성 카카오톡·문자·발신자 후보로 실제 OpenAI 증분 편집과 화면 연결을 검사하며 실제 사용자 정책은 변경하지 않는다. Phase 전체 완료나 광범위한 의미 정확도 보장을 뜻하지 않는다.

최초 실기기 실행은 실제 OpenAI 정책 검사를 통과한 뒤 화면 계층이 비어 공통 노드를 찾지 못했다. 실패 로그와 빈 계층을 보존했다. 재실행은 API 작업 후 화면을 깨우고 테스트 화면을 켜 두도록 변경했다. 실제 발신자 예외 우선순위 검사는 고정된 판단값으로 앱의 범위 적용을 검사하므로 Jev의 일반 의미 분류 정확도 검증과 구분한다.
