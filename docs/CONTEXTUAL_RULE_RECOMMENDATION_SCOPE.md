# 실제 알림에서 만드는 기준 — 2026-09-26

사용자의 Contextual Rule Recommendation UX 명세를 적용한다. 핵심은 “규칙부터 만들지 말고, 실제 알림을 보면서 하나씩 정리한다.” 기존 Phase 전체 완료를 선언하는 문서가 아니다.

## 진입과 동작

- 최초 실행에서 규칙 작성/정책 최소 1개를 강제하지 않는다. Timeline과 알림 접근 안내부터 보여준다. 기존 5단계 설정은 사용자가 설정에서 선택할 수 있다. 이전 첫 온보딩 의무 조건은 이 점진적 진입에 적용하지 않는다.
- Timeline ⋯ 또는 상세의 ‘이 알림 기준 설정하기’ → Bottom Sheet.
- 제목 ‘앞으로 이런 알림을 어떻게 할까요?’, 주 추천 최대 3개. ‘직접 말하기’ 포함. 앱 전체 숨김은 구분선 아래 별도 색상으로 분리한다. ‘그대로 두기’는 변경 없이 닫는다.
- 입력을 먼저 강요하지 않는다. 선택 → 변경 Preview → 적용/직접 수정/취소. 실제 정책 저장은 적용 이후다. 질문/Preview를 Timeline 내용과 섞지 않는다.
- ‘선택한 종류만 보기’는 선택 목록 + ‘선택하지 않은 알림은 숨김’ 안내 + ANY HIDE/SHOW 예외 미리보기다. 단순 광고 숨김과 혼동하지 않는다. 명세 10/13/21의 서로 다른 예시는 이 의미 원칙에 따라 구분한다. SHOW만 추가하고 ‘이것만’이라고 표시하지 않는다.
- 원래 앱의 Android 알림을 취소/무음화한다는 뜻이 아니다. Inbox 표시 기준이며 원본 경로를 유지한다.

## 허용 Action

고정 enum: KEEP_AS_IS / SHOW_SIMILAR / HIDE_SIMILAR / HIDE_APP / SHOW_ONLY_SELECTED_TYPES / QUIET_SIMILAR / ALWAYS_SHOW_SENDER / ALWAYS_SHOW_CONVERSATION / WATCH_CONVERSATION / CUSTOM_RULE.

현재 추천 노출: KEEP_AS_IS, SHOW_SIMILAR, HIDE_SIMILAR, HIDE_APP, SHOW_ONLY_SELECTED_TYPES, 실제 식별 정보가 있는 ALWAYS_SHOW_SENDER/CONVERSATION, CUSTOM_RULE.

QUIET_SIMILAR는 어휘/정책 확장 지점만 유지하며 추천하지 않는다. 현재 Inbox의 QUIET가 Android 원래 앱을 무음화하지 않으므로 별도 동작 차이를 검증하기 전 조용해진다고 추천하지 않는다. WATCH_CONVERSATION은 아직 미지원이므로 추천·적용하지 않는다. 지원하지 않는 행동을 LLM이 발명하거나 선택하게 하지 않는다.

## 역할과 비용

1. Jev: 의미 유형을 좁은 Noul 질문으로 판별. 추천 문구/규칙을 작성하지 않는다. 실제 반환값은 yes 확률이며 별도의 provider confidence를 만들어내지 않는다.
2. 코드: 고정 유형/확률 기준으로 허용 후보 생성과 템플릿 문구 선택. UNKNOWN/불완전 본문은 공격적인 유사 숨김 추천을 하지 않는다. 모든 추천에 사용자 선택 필요.
3. 단순한 새 기준: 사용자 선택의 고정 템플릿 → 결정론적 스키마/참조 검증 → Preview → 확인 → 저장. 현재 기준과 앱 범위가 겹치거나 레거시 기준이 있으면 이 경로를 사용하지 않는다. 기존 정책은 복사 보존한다.
4. 중첩·충돌 또는 직접 자연어: 기존 OpenAI 편집기 → JSON 검증/위험 의미 검증 → 질문 또는 Preview → 확인/저장. 단순 추천 문구를 위해 OpenAI를 호출하지 않는다.
5. 이 고정 템플릿은 **AI 생성 JSON이 아니며 사용자가 허용된 정확한 동작을 선택한 경우**에 한한다. 단순 추천에는 OpenAI를 쓰지 않는 최신 명세에 따른 예외다. 자유 생성 JSON의 기존 검증 계약을 완화하지 않는다. 모든 숨김 템플릿에도 확인을 요구한다.
6. 비용 절감을 위해 현재는 추천을 연 선택 알림에서만 Jev 의미 유형을 조회하고 내용 해시별 최근 100개를 메모리에 캐시한다. 수신 알림 전체에 추가 분류 호출을 붙이지 않는다. 예외/단순 중복 호출 방지와 기존 실시간 규칙 판정은 별개다. 개별 알림 자동 분류는 기존 Jev 정책 실행 경로 유지.
7. recommendation 목적의 호출/입력량/latency/예상 비용을 별도로 기록한다. 원문을 production log에 쓰지 않는다.

## 대화와 점진적 개인화

- 실제 conversationIdentity가 있는 알림에서 대화 유형을 한 번 선택할 수 있다. 개인 / 친구·소규모 그룹 / 업무 / 정보공유 / 기타. 나중에 선택 가능. 앱+대화 식별자 해시에 로컬 저장하며 제목에서 대화 종류를 추측하지 않는다.
- 발신자는 실제 최신 메시지의 sender가 있는 경우에만 추천한다. 알림 제목을 발신자로 간주하지 않는다. 묶음 요약은 대화 하나로 취급하지 않는다.
- 확정 적용된 로컬 템플릿의 유형/행동만 로컬 집계한다. 취소/미리보기는 집계하지 않는다. 같은 선택이 2회 이상이면 새 앱에서 ‘평소처럼 …’ 문구로 추천할 수 있으나 자동 적용하지 않는다. 자연어 수정 의미를 임의로 선호로 추론하지 않는다.
- 규칙 초기화는 선호/대화 종류도 초기화한다.
- 반복적인 대화 선택을 바탕으로 약속 확정만 제안하기, AI Watch 승격, 문맥 누적은 후속 범위다. 모델/문맥·원본 연결·불완전 메시지 안전성 검증 전 활성화하지 않는다.
- Undo는 검토 항목이다. 현재는 저장 전 취소/저장 후 기준 수정 경로를 사용한다. 이미 적용한 다른 변경을 덮어쓰는 단순 snapshot 복구로 대체하지 않는다.

## 단계와 검증

명세 Phase 1~6에 해당하는 Timeline 진입, Bottom Sheet, Jev 후보, Preview/저장, 음성·텍스트 입력, 기존 정책 수정 연결을 구현 대상으로 한다. Phase 7의 단순 로컬 선호 문구·대화 종류는 포함하며, 대화 행동 패턴 추론·Watch는 미구현으로 구분한다.

합격 기준: 지원하지 않는 행동 0, 추천 3개 이내, UNKNOWN의 유사 숨김 추천 없음, scope 임의 확대 없음, apply 전 정책 변경 없음, cancel 후 변화 없음, 중첩 정책은 검증 경로 사용, 다른 앱의 정책 보존, ‘only’ 제외 의미 보존, 로컬 템플릿의 OpenAI 호출 0, 선호 자동 적용 0. 실기기 검증 결과는 아래와 PHASE0_STATUS에 실제 완료 후 기록한다.

- 첫 회귀 중 중첩 테스트 fixture가 실제 catalog 대신 일반 Application에 앱 DB를 요청해 API까지 도달하지 못했다. 테스트에 관측 catalog를 명시한 뒤 재검증했다. 앱 동작을 통과시키기 위해 기대값을 완화하지 않았다.

- 모달을 닫거나 앱을 나가도 만들어진 미적용 제안은 기존 정책 초안 저장 경로로 이어서 검토할 수 있다. 제안을 만들기 전 종류 체크 목록/음성 입력의 프로세스 종료 복원과 정교한 Undo는 별도 검증/후속 항목이다.
