# 다국어 신뢰성 파일럿 v1 실행 결과

실행일: 2026-09-23. **첫 기준선 검사를 완료했으나 신뢰성 통과는 아니다.** Android 앱 연결이나 Phase 완료 판정은 하지 않는다. 현재 Phase 0 미완료 상태를 유지한다.

## 실행 범위

영어24 / 한국어12 / 한영 혼용4의 최초 지시40개를 OpenAI API로 검사했다. 명확한 지시32개에 합성 알림12개씩, 총384개의 알림을 작성했다. 메시지·업무·메일·스포츠·영상·소셜·납부·쇼핑·일정/여행·채용·보안·학교의 12영역이다. 나머지8개 지시는 질문·대기·미지원 상태를 검사했다.

독립 역할의 에이전트가 실행 전에 모호한 정답5곳을 수정하고 데이터 해시를 고정했다. 이는 라벨을 숨긴 사람의 독립 채점이 아니다. 기존 v3 프롬프트와 임계값을 그대로 고정했으며 이번 결과를 보고 수정하지 않았다. 실제 기기 알림·개인 메시지는 사용하지 않았다.

모델은 `gpt-4.1-mini-2025-04-14`, `jev-1.13.0`이다. OpenAI는 설정 정리만 수행했다. Jev는 정답 원문 기준384회와 OpenAI 정리문 기준264회를 별도로 판별했다. 설정이 완료되지 않은10개에 대한 후속120알림은 강제 실행하지 않았다. 정책 JSON 컴파일은 아직 없어 이번 실험은 **자연어 기준을 직접 넣는 단계별 진단**이다.

## 설정 첫 응답

|입력 언어|기대 상태와 일치|전체|
|---|---:|---:|
|영어|21|24|
|한국어|6|12|
|한영 혼용|2|4|
|합계|29|40|

명확한32개 중22개만 정리문을 반환했다. 9개는 이미 제공한 이름이나 명확한 조건을 다시 물었고 1개는 `missing_options` 검증 오류였다. 정보가 부족하거나 미지원인8개 중7개는 기대 상태였고, 후보가 없는 대화방1개는 같은 검증 오류였다. 미완성8개를 ready로 잘못 내보낸 사례는 없었지만, 이것만으로 의미 보존 성공을 뜻하지 않는다.

예: “내 이름인 서윤에게 검토나 승인을 요청하면”이라는 지시에 사용자 이름을 다시 요구했다. “서명이나 제출 요청”을 이미 말했는데 같은 조건을 다시 선택하게 하는 경우도 있었다. 일부 질문은 실제 확보되지 않은 조회수·구독 상태·메일 중요 플래그를 선택지로 제시했다.

## 알려야 할 알림이 모의 알림 결정에 도달했는가

사전 고정한 기준은 Jev 확률0.8 이상일 때 `notify`, 그 외는 `retain_for_review`다. 보관은 알림 성공이 아니다. 실제 알림 삭제·숨김은 실행하지 않았다.

|경로|알려야 할160개 중 모의 알림 도달|불필요한 알림 결정|설정 때문에 미실행|
|---|---:|---:|---:|
|원문 기준 → Jev|146 / 160 (91.3%)|3|0|
|OpenAI 정리 → Jev|101 / 160 (63.1%)|3|알림120개 중 양성50개|

정리문 경로의 미도달59개는 설정 미완료50개와 Jev 점수가0.8 미만인9개로 나뉜다. 고위험으로 표시한65개 중30개가 미도달했고, 이 중25개는 설정 미완료, 5개는 판별 점수가 임계값에 못 미쳤다. 후자의 예는 회신 마감 요구3개와 관리비 미납2개다. 일반 운영의 실제 누락률로 환산할 수 없는 작은 합성 표본이다.

언어별 정리문 경로 도달은 영어80/100, 한국어16/45, 혼용5/15다. 언어별 내용과 난도가 서로 달라 언어 자체의 성능 차이로 단정하지 않는다. 기존 프롬프트가 한국어 응답을 고정하므로 영어 질문 UX는 검사하지 않았다.

0.5 기준의 진단상 분류 정확도는 원문370/383, 정리문252/264다. 각각96.6%,95.5%지만 **설정 미완료와 실제 알림 임계값을 반영한 성공률이 아니므로 이 숫자로 신뢰성을 통과시키지 않는다.** 원문 경로의1회 HTTP520 오류는 미성공·비용 불명으로 보존했으며 재시도하여 결과를 교체하지 않았다.

## 문장 의미 검토와 추가 반례

별도 검토자가 Jev 결과를 보지 않고40개 설정 출력 전체를 원문과 비교했다. “설명만 변경은 제외”와 “장소만 변경은 제외”에서 ‘만’이 빠진 사례2개, “일반 배송 추적”의 한정어가 빠진 사례1개를 발견했다. 일부 사용자 본인과 타인의 관계·출처 앱 조건도 약해졌다. 이는 독립적인 사후 질적 검토이며 의미 정확도 점수는 아니다.

이를 확인하기 위해 원래384개에 섞지 않고 복합 조건4개를 두 경로로 추가 검사했다. 총8회 Jev 요청이다.

|추가 반례(모두 원래 알려야 함)|원문 점수|정리문 점수|
|---|---:|---:|
|시간과 설명이 함께 변경|0.93|0.54|
|취소되면서 설명도 수정|0.96|0.76|
|시간과 장소가 함께 변경|0.56|0.59|
|장소 변경됐던 일정이 최종 취소|0.82|0.88|

앞의2개는 원문 경로는 알림으로 도달했지만 정리문 경로는 보류됐다. 세 번째는 두 경로 모두 실패했다. 따라서 정리 과정의 조건 손실과 Jev의 복합 조건 판단을 함께 다뤄야 한다. 한 번의 확률 차이만으로 인과를 확정하지 않으며, 이 반례는 결과를 본 뒤 추가한 진단이지 비공개 평가가 아니다.

## 실행 비용·검사

- OpenAI 40회: 입력71,606 / 출력6,635토큰, 예상 $0.0392584. p50 1.90초 / p95 3.97초.
- Jev 기본648회: 확인된 입력333,615토큰, 예상 $0.01401183. p50 0.48초 / p95 0.58초. HTTP520 1회 비용은 확인 불가.
- Jev 추가8회: 입력4,258토큰, 예상 $0.000178836.
- 확인 가능한 API 비용 합계 약 **$0.05345**, 비용 불명1회 별도. Codex 작성·검토 에이전트 비용은 포함하지 않는다.
- 로컬 검사: 기존 설정 검사17개 + 신규 평가 무결성 검사6개 통과. 정답 비누출, 미완료 분모 유지, 보류 미성공, 데이터 수정 후 실행 차단을 확인했다.

가격 근거는 [OpenAI 모델](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [Jev 모델](https://docs.typesafe.ai/models)에서 확인했다. 사용량 기반 예상치이며 청구서 확정 금액이 아니다.

## 다음 수정과 통과 전 남은 작업

1. 이미 주어진 사실과 아직 필요한 정보를 분리해 유지하고, 주어진 이름·조건을 반복해서 묻는 문제를 수정한다. 선택지는 실제 지원 기능과 제공되는 정보로 제한한다.
2. 주체·대상·출처 앱·고유명사·‘만/일반’·AND/OR·예외의 범위를 정리 전후 비교한다. 예시를 프롬프트에 계속 덧붙이는 방식만으로 처리하지 않는다.
3. 재질문 → 답변 → 재정리, 이전 정책 변경·충돌, 후보 없음 → 최신 후보 도착 → 설정 재개를 실제 API의 다회차 시나리오로 검사한다.
4. Jev 정책 JSON 변환을 연결할 때 정리문의 조건과 JSON 의미를 별도 검사한다. 현재의 자연어 직접 판별 결과를 컴파일러 통과로 대체하지 않는다.
5. 이번 실패는 회귀 자료로 남기고 새로운 시나리오군을 별도로 평가한다. 통과율을 높이려고 원본 결과·정답·임계값을 뒤늦게 변경하지 않는다.

출력 검증 오류2개는 원시 OpenAI 응답이 저장되지 않아 내용상의 원인까지 확정하지 못했다. 다음 평가 버전에서는 합성 데이터에 한해 비밀정보 없이 검증 전 응답을 보존하는 진단 경로가 필요하다. 제품 로그에 실제 원문을 남기라는 의미는 아니다.

## 재현 및 기록

`python3 scripts/evaluate_reliability_pilot.py`는 기존 기록으로 보고서를 생성한다. `--run`은 기록이 없는 작업만 실행하며 실패 기록을 자동 재실행하지 않는다. 데이터·프롬프트·소스 해시가 달라지면 중단한다. 추가 반례는 `scripts/probe_reliability_exclusions.py`로 별도 관리한다. 새 개선 버전은 별도 실행 경로가 필요하다.
