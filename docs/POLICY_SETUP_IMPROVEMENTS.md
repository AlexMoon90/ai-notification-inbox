# 지시 정리 우선순위 개선 — 2026-09-23

사용자 요청에 따라 불필요한 재질문, 조건 손실, 답변 후 재정리를 순서대로 개선했다. 휴대폰 앱과 분리한 합성 실험이며 Phase 0 미완료 상태를 유지한다. 정책 JSON 컴파일러·Android 표시·자동 숨김은 연결하지 않았다.

## 현재 구현

현재 실험 진입점은 [policy_setup_reliable.py](../scripts/policy_setup_reliable.py)다. 기존 v3·v4·v5 파일과 결과는 비교 재현을 위해 보존한다.

1. **명확한 단일 지시 보존:** LLM이 ready로 판정하고 기존 기준/추가 답변/대화 선택이 없는 경우 코드는 원문을 그대로 최종 지시로 사용한다. 이름·원문 언어·‘만’·예외가 요약 과정에서 빠지는 일을 이 경로에서 차단한다. 이는 모델의 요약 정확도가100%가 됐다는 뜻이 아니다.
2. **재질문 기준 개선:** 이미 준 이름·대상·사건 조건과 실제 누락된 사용자 선호를 구분하는 원칙으로 프롬프트를 다시 작성했다. 실제 사용자 답변을 질문 전문·선택 내용과 함께 명시적으로 전달한다. 의미 판별을 키워드 설정으로 바꾸라고 요구하지 않는다.
3. **설정 모델 비교:** 같은 작은 모델에서 프롬프트만 고친 v4는33/40에 그쳤다. 설정 전용 모델을 `gpt-4.1-2025-04-14`로 바꾼 v5를 같은 자료로 비교했다. 반복 알림 판별은 계속 Jev다.
4. **합친 지시 검증:** 답변이나 기존 기준 변경을 반영한 ready 초안은 원문과 대조하는 추가 LLM 검사1회를 거친다. 유지할 기존 문장은 원문 표현을 보존하고, 주체·AND/OR·제외 범위·고유명사를 재확인한다. 검사 실패 시 첫 초안을 확정 가능한 상태로 남기지 않는다. 동일 모델의 재검사이므로 독립적인 정확성 보장은 아니다.
5. **질문·안내 계약:** 실제 후보를 사용하는 conversation 질문은 코드에서 scope로 분류한다. 후보 ID나 선택 내용은 바꾸지 않는다. 상태 안내는 코드가 출력해 실제 적용 전에 ‘설정 완료’라고 말하거나 지원되지 않은 사진 분석을 대안으로 약속하지 않도록 했다. ready는 사용자 검토용 초안이다.

## 기존40개 회귀 결과

|항목|v3|v4: 원칙·원문 보존|v5: 설정 모델 비교|
|---|---:|---:|---:|
|첫 응답 상태 일치|29/40|33/40|40/40|
|명확한32개 지시의 진행 차단|10|5|0|
|정보 부족/미지원8개를 ready로 오판|0|0|0|
|모의 알림 도달|101/160|미실행|148/160|
|불필요한 모의 알림 결정|3|미실행|4|

v5의40/40은 최초 HTTP429 실패3회를 별도 재시도한 회복 후 결과다. 최초40시도는 정상37/오류3이며 실패 기록은 삭제하지 않았다. 요청 시작 간격8초로 나머지를 수행했다. 원본·별도 재시도·합친 결과를 각각 보존한다. 현재 최종 안내 어댑터에도 이40개 실제 응답을 오프라인 재생하여 상태와 원문 보존을 확인했다. 새 API40회를 또 실행했다는 의미는 아니다.

v4에서는 평가기 HTTP 어댑터 별칭 누락으로 Jev 전송 전에 중단된 개발 오류가 있었다. 별칭만 수정하고 수정 전 manifest를 보존했다. v4 다회차에서 충분하지 않은 결과가 나와 Jev 전체 실행은 v5에서 수행했으며, v4의 미실행을 실패율0%나 성능 비교에 사용하지 않는다.

v5는 원문 조건으로 고유 알림384개를 실제 Jev API에 판별시켰다. 알려야 할160개 중148개가 사전에 고정한0.8 임계값을 넘었다(92.5%). 남은12개는 설정 미완료 때문이 아니라 Jev 판별 점수가 낮아서 모의 보류된 것이다. 고위험 표식이 있는 누락은3개다. 본문 명령 삽입이 있는 스포츠 결과1개는0.5 미만이기도 했다. 임계값을 낮춰 통과한 것으로 바꾸지 않았다. 실제 숨김/삭제는 하지 않는다.

언어별 사례 구성과 난도가 다르고 이미 분석한 회귀 자료이므로 실사용 정확도100%나 미사용 자료의 일반화 성능을 주장하지 않는다.

## 다회차 검증

독립 작성자가 모델 결과를 보지 않고 지시·사전 답변·후보·기대 상태10개를 작성했다. 첫 v4/v5 실행 이후 원문 대조 검사 개선에 재사용했으므로 최종 실행은 노출된 회귀검사다.

- 이름·팀·채널·중요함/긴급함을 답한 뒤 최종 지시로 반영하는5개.
- 후보가 없다가 최신 후보를 받고 실제 방을 선택하는2개. 답변 저장·디스크 재읽기도 수행한다.
- 기존 정책 부분 교체1개, 충돌 해결과 다른 기존 조건 유지1개.
- 미지원 기능을 다른 정책으로 몰래 바꾸지 않고 거부하는1개.

최종 실행에서 초기 상태와 답변 후 상태는 각각10/10 일치했다. 필수 어휘까지 포함한 자동 검사는9/10이며, 나머지1개는 영어 지시가 한국어로 정리되어 실패했다. 독립 원문 검토에서 이10개의 최종 지시에 중대한 조건 손실은 발견하지 못했지만, 질문 중 미지원 첨부 정보 선택지와 출력 언어 문제는 남았다.

검사 결과는 [최종 다회차 수치](../evaluations/policy-setup-reviewed/summary.json)와 [독립 의미 검토](policy-setup-reviewed-semantic-review.md)에 기록한다. 상태·후보 참조·필수 어휘 검사와 원문 의미 검토를 구분한다. 번역된 동일 의미가 필수 영어 단어 검사에 실패한 경우도 원래 자동실패 기록을 유지한다.

최종 지시를 실제 알림에 적용하는 추가 합성36개는 모델 출력을 보지 않은 작성자가 원문과 사전 답변만으로 만들었다. 주 작업자가36개 정답을 확인한 뒤 원문 정답 기준과 실제 최종 지시를 별도 Jev 요청72회로 비교했다. 최종 지시 경로는 알려야 할18개 중17개가0.8 이상이었고, 불필요한 적극 알림은0개였다. 나머지1개는 승인 요청을0.76으로 판정했다. 0.5 기준 의미 판정은34/36이며, 다른 방·다른 발신자 반례2개가 각각0.63/0.69였다. 원문 정답 기준 경로는13/18 도달·34/36 의미 판정으로, 동일 의도도 표현에 따라 Jev 점수가 달라지는 문제가 확인됐다. 이 작은 표본의 점수로 의미 동등성을 보장하지 않는다. [결과](../evaluations/policy-setup-reviewed/multiturn-behavior/summary.json). 방 사례는 고유한 합성 표시 이름을 사용하므로 Android conversation ID의 실제 연결 검증으로 확대하지 않는다.

## 남은 제한

- Jev 단계의 적극 알림 미도달이 남아 있어 전체 신뢰성 통과나 제품 연결 승인을 하지 않는다.
- 첫 응답 상태 정답과 질문 선택지의 지원 가능성은 별개다. 확보되지 않은 첨부 정보 등을 제안하는 질문 사례는 후속 개선 대상이다. 상태 안내의 코드 보정이 모든 질문의 의미 검증을 대신하지 않는다.
- 영어 원문을 한국어로 정리하는 출력 언어 드리프트가 다회차에서 관찰됐다. 의미 보존과 영미권 사용자 UX를 별도로 평가해야 한다.
- 정책 JSON 변환, 앱 UI 저장/재개, 실기기 알림 전달은 미검증이다. 로컬 파일 초안 저장과 실제 앱 UI를 혼동하지 않는다.
- 합성 평가만 외부 API로 보냈다. 최소 마스킹을 포함한 현재 스크립트는 실제 개인정보 처리 배포 승인을 뜻하지 않는다.

## 사용 및 재현

환경변수 또는 승인된 `.env.local`의 기존 키를 사용한다. 값은 로그에 출력하지 않는다. 다음 명령은 실제 API를 호출하며 합성 내용으로만 실행한다.

```sh
python3 scripts/policy_setup_reliable.py --session .local/demo-v6.json --instruction 'Google Calendar에서 시작 시간 변경은 알려줘. 장소만 바뀐 것은 제외해.'
```

질문이 있으면 출력된 ID에 `--question-id ID --answer '답변'` 또는 `--select 선택ID`로 응답한다. `--candidates 합성후보파일.json`으로 갱신한 뒤 제시되는 후보를 다음 실행에서 선택한다. 이 CLI는 검토용 초안을 저장하며 앱 정책을 활성화하지 않는다.

검사: `python3 -m unittest discover -s scripts -p 'test_policy_setup*.py'`. 기존 세션 계약, 현재 실제 응답40개 재생, 원문 보존, 모델/비용, 검토 실패 시 미확정, 후보 ID 보존을 포함한47개 통과.
