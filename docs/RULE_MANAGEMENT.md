# 항목별 선별 기준 관리 — 2026-09-24

후속 구현: [구조화 정책 설정 화면](STRUCTURED_POLICY_IMPLEMENTATION.md)이 새 진입점이다. 기존 문장별 항목과 실행 정책은 보존하며 확인 후 전환한다.

사용자 추가 요청으로 개인 테스트 앱에 현재 기준의 항목 목록, 적용 체크/해제, 삭제, AI 추가·수정 요청을 연결한다. Phase 0 전체 품질 게이트 완료를 뜻하지 않는다.

## 동작

- 기준 탭에서 적용/꺼짐 개수와 각 조건을 확인한다. 체크한 조건만 묶어 실제 선별 정책을 만든다. 모든 조건이 꺼지거나 삭제되면 자동 선별을 멈춘다.
- 자연어를 항목으로 나눌 때 원문의 순서·문자·전체 포함을 코드로 검증한다. 예외, 공통 범위, AND/OR처럼 서로 의존하는 조건은 묶는다. 별도 AI 검토에서 독립성을 확인하지 못하면 원문 전체를 한 항목으로 유지한다.
- 체크/삭제 변경의 컴파일 또는 저장이 실패하면 기존 항목과 정책을 유지한다. 삭제 전에는 삭제할 내용을 보여준다.
- AI는 꺼진 항목을 포함한 현재 목록과 사용자 요청을 받아 수정안을 만든다. 애매하면 선택지 또는 직접 입력으로 보충 질문한다. 변경안은 추가/수정/적용 변경/삭제/유지로 보여주며 사용자가 확인한 뒤 적용한다.
- AI 수정 요청·대화·결과는 기기에 저장한다. 확인 전에는 기존 정책으로 계속 선별한다. 그동안 현재 기준이 바뀌면 오래된 수정안 적용을 거부한다.
- 이전 입력과 미완성 초안은 현재 적용 항목과 별도로 유지한다. 기존 전체 작성 흐름은 ‘새 기준으로 전체 교체’로 접근한다.

## 역할·비용·제한

OpenAI(gpt-5.6-luna, low)는 항목 구분과 수정안/보충 질문에만 사용한다. 항목 구분과 ready 수정안에는 별도 검토 호출이 있다. Jev가 활성 조건을 하나의 정책으로 컴파일하고 새 알림을 반복 분류한다. 항목 수만큼 실시간 분류 호출을 늘리지 않는다. 항목 변경 시 지원 가능성과 해결되지 않은 충돌을 검사한다.

OpenAI/Jev 호출 수·입력량·지연·예상 비용은 기존과 별도 사용량 파일에 기록하고 알림 원문은 기준 수정 요청에 넣지 않는다. 현재 기준 자체는 AI에 전달한다. 시스템 UI 알림 수집 제외는 체크 가능한 사용자 항목보다 앞선 기본 동작이다.

최대 30항목, 활성 지시 8,000자 제한이 있다. 기존에 선택한 대화 범위는 해당 기준 묶음 전체에 적용된다. 서로 다른 대화 범위를 가진 독립 정책 여러 개의 동시 실행은 이번 구현에 포함하지 않는다. AI 수정 화면에서 새 대화 연결이 필요하면 기존 기준 만들기/대화 선택 흐름으로 안내한다. 항목 변경은 이후 새 알림에 적용하며 과거 분류를 자동 재실행하지 않는다.

AI 의미 이해와 충돌 검사는 확률적이다. 원문 대조·추가 검토·사용자 변경안 확인이 오류를 줄이지만 전체 정확도를 보장하지 않는다. 네트워크 실패 시 현재 기준은 유지되고 요청은 남지만 자동 재전송은 하지 않는다.

## 검증

단위 테스트 37개, debug/release 빌드, debug lint 통과. Galaxy S23(Android 16)에서 통합 테스트 2개 통과. 실제 API를 사용해 체크 해제/재적용 UI, AI 수정안 확인 전 기존 상태 보존 및 확인 후 반영, 삭제 UI, 저장 파일 재로드를 검증했다. AI 수정 요청/적용은 기기 테스트에서 manager 호출로 수행했고 AI 편집 화면의 전체 클릭 동선은 자동 검증하지 않았다.

사용자의 기존 활성 정책은 변경 없이 3항목으로 정리했으며 전부 적용 상태를 유지했다. 합성 테스트 API 9회, 추정 비용 $0.001323208. release APK에서 두 테스트 키 미포함 확인. 최초 빌드는 중복 생성된 `2.dex` 산출물 때문에 실패했으며 clean 후 재빌드 통과. 개발용 제한 사례 검증이며 전체 알림 정확도나 Phase 게이트 통과는 아니다. [검증 요약](../evaluations/android-app-integration/RULE_MANAGEMENT_RESULT.json).
