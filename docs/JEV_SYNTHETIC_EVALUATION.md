# Jev 합성 알림 사전 평가 — 2026-09-21

사용자 요청: 웹 UI를 만들지 않고 충분한 형태의 합성 알림과 Python 자동 판독으로 Jev를 확인한다. Android 앱에는 AI를 연결하지 않았다. Phase 0 실기기 검증의 미완료 항목은 유지한다.

## 구현 및 검증 완료

- 합성 알림 120건(12그룹), API 호출 전에 기대 정답 고정
- Jev 1.13.0에 120회 요청, 모두 HTTP 200; 재시도 없음
- 한 요청에 사건 종류 Choice와 독립 Noul 4개 질문
- 원본 응답/입력 해시/질문/모의 행동/오류/비용 기록
- 오프라인 평가기 테스트 4개 통과: 중요 알림 숨김 검출, 잘못된 응답 거부, 서비스 실패 시 보류, null 라벨 처리

## 실패와 해석

1. **앞선 대화의 미납 맥락을 놓쳤다.** “회비 3만원이 아직 미납입니다” 뒤의 “내일까지 부탁해”를 답변 요청으로 분류했다. payment_required=0.47, should_notify=0.31이었다.
2. **답변이 필요하다고 분류하면서 중요도를 낮게 판단했다.** 시안 선택 0.40, 고객 답변 0.45, 배송 주소 회신 0.49. 독립 질문들의 결과가 항상 일관적이지 않았다. 모의 규칙은 원문을 남겼지만 사용자가 기대한 적극 알림은 발생하지 않았다.
3. **약속 확정의 경계가 혼동됐다.** 일정 재조정과 렌터카/식당 예약에 meeting_confirmed를 높게 주었다. 사건 종류는 맞았다. 약속/예약 정의 자체도 사람 검토가 필요하며, 이번 점수를 높이기 위해 라벨을 수정하지 않았다.
4. **정책 경계의 이견이 있다.** 납부 요청 철회를 알려야 한다고 0.70을 주었으나 사전 라벨은 false였다. 사용자가 철회를 중요하게 여길 수 있으므로 모델 오류로만 단정하지 않고 정책 명세 검토 대상으로 남긴다.
5. **문맥 없는 확정 문구**는 UNKNOWN 대신 GENERAL로 분류했다. 원문은 보류로 유지됐다.
6. **형식 검사 1건 실패의 원인은 확률 합 0.99다.** context-05는 JSON 파싱·필드·값 범위 모두 정상이었고 GENERAL 및 4개 이진값도 기대 정답과 일치했다. Choice 확률 합이 1.00에서 0.01 차이 나 사전 고정 허용 오차 0.001을 넘었다. 반올림 영향으로 추정되며 JSON 생성 실패가 아니다. 이번 실행의 엄격 채점 결과는 유지한다. 참고로 이 응답도 포함한 원본 범주 일치는 118/120, 전체 필드 일치는 111/120이다. 운영 파서의 반올림 허용 여부는 별도 결정해야 한다.

## 제한과 다음 단계

중요 알림 숨김 0건은 정확도가 완벽하다는 뜻이 아니다. 엄격한 광고 조건에서만 숨기고 나머지를 보류한 덕분이며, 중요한 79건 중 19건은 적극 알림되지 않았다. 현재 결과로 자동 숨김이나 유료 서비스 품질을 보증할 수 없다.

단일 작성자의 합성 자료이며 실제 알림 분포, 중복·그룹 요약, 긴 대화, 앱별 원문 형식, 사용자별 선호를 대표하지 않는다. 같은 문장에 앱 이름만 순환 배정한 부분은 앱별 품질 검증이 아니다. 각 사례 1회라 출력 안정성도 아직 검증하지 않았다. timeout/재시도 코드는 있지만 실제 장애 주입 검증은 하지 않았다.

다음에는 문맥 누락·행동 요구·예약 경계를 별도 신규 세트로 만들고, 질문 정의 또는 코드의 보수적 판단 규칙 변경을 비교해야 한다. 사용자 요청 범위의 합성 평가만 완료했으며, 실제 수집 알림 100~200개 평가 및 Android 연동을 포함한 Phase 1 전체 완료로 간주하지 않는다.
