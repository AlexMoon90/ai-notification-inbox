## 현재 구현과 추가 범위

현재 [항목별 기준 관리](RULE_MANAGEMENT.md)는 자연어 항목과 enabled를 저장하고 켜진 문장을 하나의 실행 정책으로 합친다. 전체 묶음에 같은 대화 연결을 사용하며 AtomicFile에 보관한다. 체크/해제·삭제·AI 수정안·확인 적용은 구현됐지만, 아래 구조화된 정책 모델·Room 정책 저장·다중 정책 엔진까지 구현된 것은 아니다.

| 영역 | 현재 | 추가할 내용 |
|---|---|---|
| 정책 데이터 | 문장 항목 + 적용 상태 | Policy / Scope / Condition / Action / Exception, 원문·버전·생성/변경 시각 |
| 적용 대상 | 하나의 묶음에 고정된 대화 연결 | 정책별 앱·대화·발신자·관계·소스 유형 |
| 조건·동작 | 자연어 정책 전체의 일치 판단 | 조건 조합 및 SHOW / QUIET / HIDE / WATCH |
| 저장 | 정책·항목 AtomicFile, 알림 Room | 정책·예외·초안·활성 버전 Room, 기존 데이터 이관 |
| 충돌 | 충돌 감지 시 변경 거부 | 구체성·명시적 예외·최신 명시 변경 비교, 미해결 재질문 |
| 설정 화면 | 문장 목록·체크·삭제·AI 편집 | 범위별 그룹과 하위 예외, 조건/동작 표시, 동작 직접 변경 |
| 변경 확인 | 전체 항목의 변경 표시 | 변경 중심 Diff, 유지 항목 요약/펼치기 |
| AI Watch | 미구현 | 같은 정책 체계의 WATCH와 선택 대화 문맥 연결 |

## 저장 계약과 의미 보존

Policy는 id, name, enabled, scope, conditions, action, exceptions, sourceInstruction, createdAt, updatedAt을 갖는다. 앱이 schemaVersion, policy revision, 초안/활성 상태와 명시적 변경 근거를 관리한다. 원문은 근거로 보존하되 실행은 검증된 구조를 사용한다.

- Scope: appIds[], conversationIds[], senderIds[], relationship, sourceType. 전체 앱, 특정 앱, 특정 대화, 특정 발신자, 관계, 소스 유형을 표현한다. 여러 범위 필드의 결합과 동일 필드 내 복수 대상의 의미를 명시한다(기본: 필드 간 AND, 같은 필드 값 간 OR).
- Condition: type, operator, value, 필요 시 confidenceThreshold. 여러 조건의 ANY/ALL/NOT 의미를 명시해 AND/OR를 잃지 않는다. 임계값은 검증 설정이며 AI가 임의 생성하거나 사용자가 JSON으로 입력할 항목이 아니다.
- Action: SHOW, QUIET, HIDE, WATCH만 초기 허용한다. NOTIFY_NOW, 캘린더/할 일 후보 및 SEND_TO_WATCH 등은 후속 범위다.
- Exception: 부모 정책에 연결된 조건·동작과 식별자를 갖는다. 부모를 끄면 하위 예외도 실행하지 않는다. 부모 삭제 시 예외 처리도 미리 보여주고 원자적으로 변경한다. 예외를 독립 일반 정책으로 자동 승격하지 않는다.
- 현재 문장에 있는 사용자 정의 내용(기타 장비 할인, 특정 팀 경기 결과, 특정 채널 등)은 type 분류만으로 소실시키지 않는다. 허용된 value/내용 조건으로 표현하거나 지원 불가 초안으로 남긴다.

초기 조건 타입은 MEETING_CONFIRMED, SCHEDULE_CHANGE, PAYMENT_REQUIRED, MONEY_RECEIVED, REPLY_REQUIRED, ACTION_REQUIRED, DELIVERY, RESERVATION, SECURITY, IMPORTANT_NOTICE, PROMOTION, CASUAL_CHAT, USER_MENTIONED, AI_TASK_COMPLETED, AI_INPUT_REQUIRED다. Watch의 MEANINGFUL_CHANGE도 Watch 검증 단계의 허용 계약에 포함한다. 기존 event_type과 정책 condition type은 별개이며 명시적 매핑을 둔다. 새 타입은 버전 관리된 허용 스키마로 추가한다. 정책 편집 JSON의 미허용 enum/필드는 거부하며 UNKNOWN으로 자동 치환해 저장하지 않는다. 런타임 알림의 분류 불확실성만 UNKNOWN으로 처리하고 숨기지 않는다.

원문의 ‘값이 없으면 넓은 범위’는 **사용자가 의도적으로 제한하지 않은 필드**에만 적용한다. 이름을 모르는 회사 방, 후보 만료, 식별자 누락, 관계 미확정은 미해결 상태다. 이를 null로 지워 전체 앱 정책으로 활성화하지 않는다. 관계는 사용자 연결 또는 검증된 근거가 필요하며 대화 제목만으로 확정하지 않는다.

‘일정 변경만 알려줘’는 일정 변경 SHOW 하나로 바꾸면 의미가 달라진다. 해당 범위의 비일치 처리(HIDE 또는 QUIET)를 함께 구조화하고 사용자에게 확인한다. 일반적인 ‘일정 변경도 알려줘’에 그런 제외 조건을 추가하지 않는다.

## 실행과 충돌 규칙

OpenAI는 의도 정리·보충 질문·정책 JSON 생성/수정, Jev는 활성 규칙의 반복적인 의미 일치 판단, Policy Engine은 검증된 의미 결과와 현재 활성 정책의 매칭·우선순위, 앱은 행동을 담당한다. 코드가 키워드만으로 의미를 새로 추론하거나 일반 알림마다 LLM을 호출하지 않는다. 공유 가능한 의미 판단은 재사용하고 정책 수 증가에 따른 API 호출·입력량·지연·비용을 측정한다.

사용자 원문의 기준을 앱 코드에 명시적으로 구현한다.

1. 적용되는 정책의 Scope 구체성을 비교한다. 기본 비교는 특정 대화 > 특정 앱 > 특정 관계 > 전체 앱이다.
2. 해당 부모에 속한 명시적 예외는 부모 정책보다 우선한다. 이 부모/예외 규칙을 서로 무관한 정책 전체의 무조건 우선권으로 확대하지 않는다.
3. 여전히 상충하면 사용자가 해당 범위와 동작을 명시적으로 변경한 최신 지시를 적용한다. 단순 저장 시각, 마이그레이션 시각, 마지막 AI 응답만으로 우선권을 만들지 않는다.
4. 비교할 수 없는 발신자/대화/관계 조합이나 동순위 상충은 구체적 상황을 보여주고 사용자에게 확인한다. 의미가 해결되지 않은 수정은 기존 활성 버전을 대체하지 않는다.

발신자·소스 유형 및 복합 Scope의 비교표는 Phase A에서 고정하고 테스트한다. 단순히 필드 개수가 많다고 더 구체적이라 추측하지 않는다. 결정 근거에는 적용 정책·예외·버전을 남겨 사용자가 ‘왜 이렇게 처리됐는지’ 확인할 수 있게 한다.

일치 정책이 없으면 default_action=SHOW다. 불확실한 의미·UNKNOWN·본문 누락·긴 내용·정보 부족·API 실패에도 숨김보다 표시/원본 확인 필요를 우선한다. 이는 수집 단계에서 제외하는 android/com.android.systemui 알림까지 다시 가져온다는 뜻이 아니다. 명시적인 ‘이것만’ 정책의 비일치 처리와 정책 자체가 없는 경우를 구별한다.

SHOW는 Inbox 표시, QUIET는 조용히 확인 가능한 표시, HIDE는 메인 Timeline 제외로 정의한다. 원래 앱/OS 알림 삭제·차단과 혼동하지 않는다. 앱 자체 푸시가 없는 현재 구현에서는 SHOW/QUIET에 알림음 차이가 이미 있는 것처럼 표시하지 않는다. 별도 통지 동작은 구현·검증 후 노출한다.

WATCH는 선택 대화의 관찰 문맥 누적·변화 판단 등록이다. 단순 SHOW/HIDE와 같은 즉시 표시 명령으로 처리하지 않는다. Watch가 검출한 사건은 표시 정책과 예외를 다시 적용한다. WATCH와 표시 정책이 함께 매칭되는 경우의 동작을 엔진 검사에 포함한다. 미지원 상태에서는 활성화하지 않고 준비 중으로 안내한다. 세부 문맥·보관·중복·요약 제한은 [AI Watch 범위](UI_UX_AI_WATCH_SCOPE.md)를 유지한다.

## Settings UX

‘현재 알림 기준’에서 모든 앱 / 회사 / 친구·모임 등 범위별로 묶고, 각 항목에 조건 → 동작과 ON/OFF·수정·삭제를 보여준다. 실제 앱·대화 대상과 미지정 관계를 확인할 수 있어야 한다. 예외는 부모 아래 들여쓰기해 관계를 표시한다. 일반 Timeline은 기존 compact row 방향을 유지하며 정책 설정용 계층/카드를 Timeline 전체 디자인으로 확대하지 않는다.

MVP 직접 조작 최소 범위는 켜기/끄기, 삭제, Action 변경, Scope/Condition 확인이다. Scope 직접 변경도 개발 범위에 포함하되 기존 실제 후보 선택 컴포넌트로 유효한 대상을 선택하게 한다. 구현 순서상 최소 편집 다음에 연결한다. 임의 ID 입력, 복잡한 계층 drag/drop, custom category builder는 제외한다.

자연어 추가·수정 → 보충 질문 → OpenAI JSON 생성 → 앱 결정론적 검증 → 위험이 있을 때만 추가 의미 검증 → 사람이 읽는 변경안 → 확인/수정/취소 → 원자적 저장 흐름을 제공한다. Diff는 추가/변경/삭제를 우선 보여주고 유지 항목은 요약하며 필요하면 펼친다. 화면을 나갔다 와도 초안과 응답을 이어가고, 적용 실패·오래된 수정안은 기존 활성 정책을 보존한다. 직접 Action/Scope 변경에도 영향과 충돌을 검증하고 필요한 확인을 받는다.

## 구현 순서와 완료 조건

아래 A~F는 원문에서 요청한 **이번 정책 확장의 내부 작업 순서**다. 기존 프로젝트 Phase 0~6을 대체하거나 완료 처리하지 않는다.

| 순서 | 개발 내용 | 다음 단계 진입 전 확인 |
|---|---|---|
| A | 데이터 모델·허용 schema·조건 조합·우선순위 계약 | 예외/‘만’/UNKNOWN/미해결 대상의 의미 보존, 결정표 테스트 |
| B | Room 정책 저장·버전·초안·이관 | 기존 활성 기준·꺼짐 항목·초안·대화 연결 보존, 원자적 실패 복구 |
| C | 다중 정책 엔진·Scope/Condition·예외/충돌 | 결정론적 매칭, default SHOW, 불확실한 알림 숨김 방지 |
| D | 그룹/계층 목록·체크·삭제·직접 편집 | 현재 적용 상태 이해, 부모/예외 관계, 실제 후보 범위 변경 |
| E | OpenAI JSON → 앱 검증 → 확인 파이프라인 연결 | 원문/구조 대조, 미해결 재질문, 변경 승인 전 기존 정책 유지 |
| F | 변경 중심 Diff·전체 회귀 | 추가/변경/삭제/유지 구분, 재시작·중단·동시 수정·Galaxy 검증 |

기존 항목 목록은 일괄 자동 변환해서 즉시 새 엔진에 넣지 않는다. 원문·기존 활성 동작을 보존한 이관 초안을 만들고 의미 대조와 회귀를 통과한 뒤 새 모델로 전환한다. 모든 기존 문장을 근거 없이 SHOW로 바꾸지 않는다. Room 저장 실패나 변환 불가 시 기존 저장소/정책을 보존한다.

필수 검증에는 광고 숨김+기타 장비 예외, 회사 광고 충돌, 대화/앱/관계 우선순위, 동순위 재질문, 명시적 최신 변경과 단순 시각 변경 구분, ‘만’과 ‘도’, ANY/ALL, 조건 일부 UNKNOWN, 부모 OFF/삭제, 이름 같은 다른 대화, 미해결 대상, AI 작업 완료/승인 요청, WATCH 중복·표시 정책 병존을 포함한다. 한국어와 영어 및 기존 영미권 앱 시뮬레이션을 재사용한다.

실제 코드·단위·API·실기기 결과를 따로 기록한다. 기존 37개 단위/2개 기기 테스트는 이전 항목 관리 구현의 결과이며 새 구조화 정책 엔진 통과 근거로 재사용하지 않는다. 작업량은 기존 설정 UX/Watch 범위와 중복되므로 기존 견적에 전체를 단순 가산하지 않고 Phase A 계약 확정 후 잔여 작업을 재산정한다.

## Policy JSON Validation 추가 계약

[검증 파이프라인](POLICY_JSON_VALIDATION.md)을 필수 적용한다. strict schema, 앱이 계산한 Diff와 대상/범위/예외 검사, 위험 기반 OpenAI 의미 검증, valid/invalid/clarification_required 처리, 위험별 사용자 확인과 revision 검증을 포함한다. 현재 구현의 일괄 추가 AI 검토와는 다른 목표 설계이며 아직 연결되지 않았다.

## 첫 온보딩과 시간 조건 확장

[첫 온보딩 가이드 반영](FIRST_ONBOARDING_SCOPE.md)으로 공통 모델에 Time Condition을 추가한다. 자정 통과 시간대·요일/주말·업무시간·임시 기간·시간대를 계약화하고 종료 후 기본 정책 재적용을 검증한다. 별도 온보딩 실행 JSON을 만들지 않는다. 원문에는 없었던 후속 사용자 범위이며 기존 앱에서 지원된 것으로 표시하지 않는다.
