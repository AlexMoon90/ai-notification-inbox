# v5 지시 흐름 사후 독립 의미 검토

검토일: 2026-09-23. 평가 데이터와 OpenAI 설정 응답만 읽었다. Jev API 분류 점수·응답은 읽지 않았다. 데이터·코드·프롬프트를 변경하지 않았다. AI 검토자가 실행 이후 출력을 읽고 판단한 질적 검토이며 독립 사람 채점이나 봉인된 의미 정확도 측정이 아니다.

## 첫턴 40개

`evaluations/policy-setup-v5/effective-settings.jsonl` 40개를 원문과 비교했다. ready 32개는 원문 및 change_summary가 원문으로 보존되고 질문이 없다. 명시된 이름을 다시 묻거나 한정어를 없애는 문제는 이 유효 응답에서 발견하지 않았다. 다만 이는 원문 보존 코드와 ready 판단의 조합이며 32개의 자연어 요약 능력을 검증한 것이 아니다.

needs_input 4개는 팀 이름/주관적 의미를 질문하고, waiting 1개는 후보 도착을 기다린다. 미지원 3개는 normalized_instruction=null을 유지하므로 동의 없이 다른 정책을 적용한 것은 아니다.

상태 정답과 별개로 남은 안내 문제:

- **pilot-038:** 물리적 배송 여부 미지원 안내 뒤에 ‘알림에 사진이나 추가적인 증거가 포함된 경우, 해당 내용을 바탕으로 안내해드릴 수 있습니다’라고 했다. 현재 제공 기능은 알림 텍스트·메타데이터이며 이미지 해석을 지원한다고 확인하지 않았다. 사용자가 사진 분석 기능이 있는 것으로 오해할 수 있다.
- **pilot-034:** ‘unless Casey has appeared in a notification or is included in the provided group candidate list’라는 예외를 붙였다. 발신이 관찰된 방을 아는 것과 전체 참여자 명단 또는 Casey가 참여한 모든 방을 아는 것은 다르다. unsupported 상태는 맞지만 가능한 범위를 더 정확히 설명해야 한다.
- **pilot-035/039/040:** 조회수·좋아요·구독 상태처럼 명백히 확보하지 못한 지표를 선택지로 주는 문제는 이번 출력에서 발견하지 않았다. 채널·이름·멘션·키워드는 이후 실제 관찰 가능 여부와 사용자 값을 채워야 한다. 주관적 중요도를 키워드 위주로 유도하는 UX 경향은 남아 있다.

`effective` 기록은 실패 재개 후 유효 결과를 모은 것이다. 서비스 오류가 없었다는 뜻이 아니며 최초 실행의 API 실패는 원기록에서 따로 보고해야 한다.

## 비교 참고: v4 다회차 자동 실패의 해석

v4의 자동 통과 4/10을 의미 정확도 40%로 해석하지 않는다.

- mt-005는 영어 `today`/`approval` 출력에 한국어 `오늘`/`승인` 필수어 검사가 실패했다. 어휘 검사 오탐이지만 ‘내 승인’ 주체가 정리문에서 약해진 문제와 초회 미지원 중요 플래그 선택지는 별도로 남는다.
- mt-009는 유나 조건의 실제 충돌을 올바르게 질문했지만 field를 `conflict` 대신 `meaning`으로 표기해 실행기가 답변을 전달하지 않았다. UI 계약 불일치이며 ‘충돌을 이해하지 못했다’는 증거는 아니다. 후속 Calendar 보존은 실행되지 않아 검증되지 않았다.
- mt-003은 답변 뒤에도 구체적인 미납 납부 요구를 재질문했고, 초회 Gmail 내부 중요 표시·라벨을 선택지로 제시했다. 이는 어휘 검사 문제가 아니다.
- mt-004는 `missing_options`, mt-006/007은 `unexpected_candidate` 계약 오류로 중단됐다. 완료된 의미 결과가 없으므로 통과로 바꾸지 않는다.
- mt-001/002는 정책 내용이 맞아도 ‘is set’/‘설정이 완료되었습니다’처럼 실제 활성화 전 완료를 암시하는 문구가 있었다.

### mt-008: 기존 Gmail 조건 보존 실패

기존 조건은 `Gmail messages explicitly saying my bill is overdue`다. 의미상 사용자 청구금이 연체됐다는 알림을 말한다. 실제 최종 지시는 다음과 같다.

> Gmail 메시지 중 'bill is overdue'라는 문구가 명시된 경우에만 알림을 받고 ...

‘my bill’을 포함한 의미 조건을 특정 영어 문자열이 명시된 경우로 바꿨다. `Your payment is past due` 또는 같은 의미의 한국어 알림도 원래 기준에 해당할 수 있는데 변경 지시는 배제할 수 있다. 또한 사용자 본인의 청구라는 관계도 약해졌다. message/change_summary에는 ‘Gmail 규칙은 변경하지 않습니다’라고 써 실제 전달 지시와 설명이 다르다. 이는 단순 번역/필수어 오탐으로 처리할 수 없다.

이 비교에서 Cedar Science는 최종 normalized_instruction에 없고 변경 설명에만 이전 값으로 등장한다. 이전 값의 설명상 등장을 정책 잔존으로 오판하지 않았다. YouTube 예외는 유지됐다.

### mt-009: 존재하지 않던 신원 구분의 명시

사용자는 유나 메시지를 알릴지 말지 모순된 요구를 한 뒤 ‘유나가 보낸 메시지는 모두 알려주는 쪽’이라고 정리하고 Calendar는 유지하라고 답했다. 최종 지시는 다음 문장을 추가로 명시한다.

> 유나가 보낸 메시지가 아닌 경우에도 발신자 표시가 유나인 메시지는 알림을 받는다.

초기 지시에 발신자 표시 조건이 있었으므로 단순히 새로운 표시 이름 범위를 추가했다고 단정할 수는 없다. 그러나 알림의 표시 이름과 별개로 **실제 인물이 유나인지 판별할 수 있는 것처럼** 구분하고, 이를 사용자가 별도로 선택한 예외처럼 풀어 썼다. 관찰 가능한 표시 이름 기준으로 표현해야 하며, 실제 신원 구분이 필요하다면 그 증거가 없다. 자동 검사에서 Calendar와 유나 등의 단어가 남는다는 사실로 이 문제를 찾을 수 없다.

## 결론과 다음 검증 범위

첫턴 상태가 모두 맞아도 안내문에서 기능을 과장하거나, 다회차에서 기존 기준을 키워드 조건으로 바꿀 수 있다. 이 실행에서 확인한 개선은 명확한 최초 지시의 원문 보존, 중복 질문 감소, 미지원 상태 유지다. 기존 기준 병합과 관찰 가능한 범위의 일관된 설명은 추가 개선이 필요하다.

다음 버전에는 언어 독립적인 의미 검사, 질문 kind/field 계약의 명확한 정의, 활성화 전 완료 안내 차단, 기존 조건의 의미·주체 보존 검사를 넣어야 한다. mt-006/007의 마지막 단계는 실제 사용자 선택 후까지 다시 실행해야 하며, 이미 본 10개에서의 재검사는 개발 회귀 검증으로 보고해야 한다. 이번 자료를 사용한 개선 후 점수를 독립 일반화 성능으로 주장하지 않는다.
