# 구체적 사용자 요구 16가지 실험 — 2026-09-22

사용자 요청으로 자연어 요구에 따른 스마트 자동 분류를 실제 Jev API에 적용했다. 8가지 주제마다 상반된 요구 2개를 만들고 같은 알림 8개씩 입력했다. 64개 합성 입력 × 정책 2개 = 128회. 모든 기대 정답과 질문은 실행 전에 고정했고 결과에 맞춘 재실행/라벨 변경은 하지 않았다.

## 결과

- HTTP 및 JSON 검증: 128/128 성공, 재시도 없음
- 사건 종류: 121/128 (94.5%)
- 정책에 따른 중요 여부: 119/126 (94.4%). 방 종류 미상인 2건은 정답 보류로 제외
- 중요한 사례: 51건 중 3건 누락 (48/51 포착)
- 알리지 말아야 하는 사례: 75건 중 4건 과잉 판정
- **정책에 따라 결과가 반대로 나와야 하는 31쌍 중 29쌍 양쪽 정답**
- 중요 점수 0.8 기준의 모의 적극 알림은 중요 사례 39/51. 나머지 12건은 원문 유지·보류. 0.5 정확도와 실제 적극 알림 비율은 구분
- 방 종류 미상 2건은 모두 원문 유지·보류
- 호출 p50 662ms / p95 792ms
- 입력 172,688 / 출력 16,506 토큰, 추정 비용 $0.007253. [공식 가격](https://docs.typesafe.ai/models) 입력 100만 토큰당 $0.042, 출력 무료 적용. 실제 청구서 미확인

## 잘된 요구와 실패

8건 모두 중요 여부를 맞힌 요구: 확정 약속만 / 제안·변경도 포함 / 광고 제외하고 실제 거래만 / 엄마 메시지 우선 / 보안만 / 현재 내 이름 언급 / 완료 제외하고 변경·취소만 / 회사개발방 행동 요청만. 개인방만 요구도 알려진 방 종류 7/7, 미상 1건 보류였다. 이 소수 사례 통과가 요구 전체의 완전 구현을 뜻하지는 않는다.

실패한 중요 판단 7건:

1. 미납 맥락 뒤 “내일 오전까지 부탁드려요”: 두 정책 모두 0.49/0.43으로 누락. 사건 종류는 납부로 맞혔지만 중요 여부가 일치하지 않았다.
2. 커피 쿠폰 허용·호텔 광고 제외 설정에서 실제 숙소 체크인 안내를 0.26으로 누락. 광고 제외가 실제 거래까지 번진 것으로 추정.
3. 카카오톡 단톡방만 설정했는데 Slack 알림을 0.56으로 과잉 판정. 앱 범위 검사는 명시적인 코드 조건으로도 보장해야 한다.
4. 답변 요구만 설정했는데 “요청하신 수정은 모두 완료”를 0.57로 과잉 판정.
5. 배송 완료·예약 접수·발권 완료 설정에서 예약 시간 변경을 0.63으로 과잉 판정. **이 정책은 ‘그 밖에는 알리지 마’가 명시되지 않아 사전 라벨과 해석이 다를 여지가 있다.** 순수 모델 오류로 단정하지 않고 요구 명확화 대상으로 기록한다. 점수는 사전 라벨 그대로 유지.
6. 가족방 행동 요청만 설정했는데 “자료 확인, 끝났어요”를 0.71로 과잉 판정.

범주 라벨에는 요청 철회/타인의 미납/제안과 답변 요청의 경계가 있다. 이번 taxonomy에서는 부정·철회 및 사용자 납부 의무 없음은 GENERAL로, 타인에게 회신을 요구하는 문장의 사건 종류는 REPLY_REQUIRED로 정했다. 이 정의를 제품 범주 정의로 확정한 것은 아니다.

## 구현 범위와 판단

Python이 Jev 원본 JSON을 앱용 category/should_notify/category_confidence/action으로 변환하고 자동 판독하는 경로는 구현·실행했다. **자연어 요구를 state.policy에 직접 주는 분류 실험이며 정책 JSON 컴파일이나 LLM 정규화, Android 연동까지 구현된 것은 아니다.** 실제 개인 알림과 OpenAI API는 사용하지 않았다.

개인방/단톡방·앱·방·발신자 조건과 의미 조건을 함께 적용할 가능성은 확인했다. 다음 단계에서는 앱/방 ID 등 확정 메타데이터는 코드로 제한하고, Jev는 의미 판단을 담당하게 하는 편이 적절하다. 정책 예외와 문맥 독촉은 새 세트로 더 검증해야 한다. 이번 응답으로 자동 숨김을 실행하지 않았다.

검증: 조건쌍의 입력 동일성/정답 비누출/미상 그룹 처리 테스트 2개 통과. 128개 고유 결과와 키 비노출 확인. 합성 자료이며 단일 작성자가 라벨링했다. 실제 사용자 정확도나 사용 경험의 완료 판정으로 확대하지 않는다.
