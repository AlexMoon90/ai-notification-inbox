# 새 기준 음성 입력 및 저장 정책의 증분 편집 — 2026-09-24

## 요청과 구현

- 알림 기준 화면의 상단 추가 버튼을 제거하고, 하단 탐색 메뉴 바로 위 가운데에 ‘새 기준 추가’를 고정한다.
- 새 요청을 열면 이전 문장을 채우지 않는다. 저장된 정책 JSON은 입력창에 복사하지 않고 서버 요청의 `previous_rules`로 별도 전달한다.
- 새 요청 버튼은 Android `ACTION_RECOGNIZE_SPEECH`를 자동 실행한다. 휴대폰의 음성 인식 앱이 녹음/인식하고 반환한 문장을 편집창에 표시한다. 음성 서비스의 권한·네트워크·언어 지원은 기기에 의존한다.
- 인식 취소·서비스 부재 시 직접 입력 또는 마이크 재시도가 가능하다. 자동 재시작하지 않는다. 음성 인식 성공만으로 OpenAI 호출/정책 적용을 하지 않는다. ‘확인하고 정리’ 후에만 요청한다.
- 화면의 기존 기준 상세/AI 수정/추가 설정은 유지한다. AI 수정은 해당 기준 이름을 안내하지만 과거 전체 입력 문장을 재사용하지 않는다.
- 작성 중 취소 후 ‘새 기준 추가’를 다시 누르면 새 빈 입력으로 시작한다. 보충 질문의 답변·기존 검토안 재시도는 별도의 기존 경로에서 대화 이력을 유지한다.

## OpenAI에 실제 전달하는 가이드

`PolicyController.EDITOR`와 `SEMANTICS`, `PolicyContract.editorFor(previous_rules)`를 사용한다. `SetupEngine.structured`의 Responses API `text.format`은 `json_schema`, `strict=true`다.

입력은 저장된 `previous_rules`, 이번 요청/보충 답변의 `conversation`, 실제 대상 후보 `catalog`, 지원 조건의 실행 의미 `condition_catalog`, 새 기준용 허용 ID, 현재 시각이다. 이전 방식 정책을 변환할 때만 legacy 지시와 항목을 함께 전달한다.

저장된 규칙의 순서·ID·과거 source_instruction은 현재 대화가 아니므로 “그 기준”의 대상을 결정하는 근거로 쓰지 않는다. 여러 후보가 있으면 편집기와 의미 검증기가 모두 재질문하도록 명시했다.

이번 보강은 새 요청을 기존 기준 전체 교체로 해석하지 않기, 동등한 규칙의 중복 추가 금지, 명시적 수정 시 기존 ID 유지, 대상/뜻이 여러 가지면 질문하기다. 출력은 전체 규칙과 실제 변경 작업을 포함하고, 무관한 기준과 꺼짐 상태를 보존한다. 스키마/결정론적 검사 → 위험 시 의미 검사 → 보충 질문 또는 변경 비교 → 확인/저장 순서를 유지한다. Jev는 규칙 생성에 관여하지 않는다.

형식 준수만으로 의미 정확도를 보장하지 않는다. [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Android RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent).

## 검증

최종 결과는 `evaluations/policy-voice-edit/result.json` 참조. 실제 음성의 단어 인식 정확도와 여러 OEM 지원은 별도 확인 대상이다. 테스트의 합성 음성 반환은 마이크의 실제 음향 인식을 대체하지 않는다. 기존 Phase 전체 품질 게이트 상태는 변경하지 않는다.

최종 빌드·lint 및 단위/렌더링 61개 통과. Galaxy 합성 음성 결과/빈 신규 입력 테스트와 실제 OpenAI 추가→동일 ID 수정→대상 미확정 재질문 테스트 2개가 통과했다(42.378초, API 4회, 추정 $0.00327634). 첫 실행에서는 불명확한 “그 기준”을 ready로 반환해 실패했고, 과거 정책 문장/배열 순서를 현재 대화로 해석하지 못하도록 공통 가이드를 보강한 뒤 전체 두 테스트를 다시 실행했다. 실패 로그도 보존한다. 이는 제한된 회귀 사례 통과이며 일반 정확도 보장이 아니다.

Galaxy 실제 하단 버튼에서 Google 음성 인식 서비스가 자동 실행되고 취소 후 편집창 복귀를 확인했다. 실제 발화의 음향 인식 정확도는 미검증이다. 사용자 실제 기준은 테스트 전후 동일함을 확인했다.
