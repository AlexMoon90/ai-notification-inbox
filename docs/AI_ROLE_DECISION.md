# AI 역할 변경 결정 — 2026-09-24

후속 앱 구현: [구조화 정책 구현 기록](STRUCTURED_POLICY_IMPLEMENTATION.md). 새 설정 경로에서 Jev 컴파일을 제거했고 기존 기준은 사용자 확인 전까지 보존한다. 아래 ‘이번 작업’은 역할 결정 당시 문서 반영 기록이다.

사용자 최신 지시에 따라 이전의 ‘LLM 정리 → Jev 정책 JSON 생성’ 설계를 대체한다. 보관된 사용자 원문과 이전 구현·평가 기록은 당시 사실로 유지하며, 앞으로의 개발에는 이 결정을 우선 적용한다.

## 목표 흐름

```text
사용자 자연어 + 기존 규칙 + 실제 대상 후보 + 앱 지원 범위
→ OpenAI: 의도 정리 / 모호함·충돌 보충 질문 / 규칙 JSON 생성·수정
→ 앱: 스키마·실제 대상·지원 기능·버전·명시적 우선순위 검증
→ 위험 변경에 한해 OpenAI 의미 검증 / 필요 시 재질문
→ 사람이 읽는 항목과 변경 내용 확인
→ 사용자 확인 → 활성 정책 원자적 저장

새 알림 + 활성 규칙
→ 앱: 명확한 대상 범위 확인
→ Jev: 규칙의 의미 조건에 해당하는지 판단
→ 앱: 예외·우선순위·불확실성 처리 → 표시/조용히/숨김/Watch
```

OpenAI는 Scope / Condition / Action / Exception 구조의 실행 정책 JSON을 직접 생성한다. Jev는 규칙을 생성·수정·재해석해 저장하지 않으며 정책 지원 가능성/컴파일 승인 게이트로도 호출하지 않는다. Jev의 판단 결과가 JSON인 것은 허용하되, 이는 정책 JSON 생성과 다른 역할이다. Watch에서도 사용자 규칙에 해당하는 변화/참여 시점의 의미 판단만 맡는다. 기존 승인된 조건부 OpenAI 짧은 요약은 유지한다.

켜기/끄기·삭제·명확한 Action/Scope 직접 편집은 앱이 검증 후 구조를 변경한다. 매번 AI로 다시 작성하지 않는다. 자연어 해석이나 해결되지 않은 의미 충돌이 필요할 때 OpenAI 보완 흐름으로 연결한다. 직접 조작도 삭제·범위 확대·숨김 등 위험에 해당하면 별도 의미 검증과 필요한 확인을 거친다. 규칙 설정·변경 경로의 Jev 호출은 0회, 일반 알림 반복 판단 경로의 OpenAI 호출은 0회를 검증한다.

## JSON 및 의미 검증

OpenAI Structured Outputs로 앱이 정한 JSON Schema에 맞춰 출력받는다. 스키마 일치는 의미 정확성 보장이 아니며, 거절·불완전 응답·잘못된 값은 활성화하지 않는다. [공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs).

앱은 허용 조건/동작, 실제 후보 ID, 미해결 범위, 부모/예외 참조, ANY/ALL/NOT, 버전과 수정 기준 버전을 검증한다. 구조로 판정 가능한 충돌은 코드로 검사하고, 의미가 모호한 충돌은 OpenAI가 질문하도록 한다. 사용자 원문과 수정안 대조로 누락·무단 추가·‘만’ 조건 및 예외 소실을 검증한다. 알 수 없는 대상을 전체 범위로 확대하지 않는다. 확인 화면은 실제 저장할 JSON에서 생성해 표시와 실행의 불일치를 막는다.

원문·기존 정책·변경 의도에서 기대 JSON을 정의하고, JSON 정확성과 Jev 알림 일치 판단을 별도 평가한다. 영어/한국어, 광고 예외, 복합 조건, 부분 변경, 모순, 미확정 대상, 오래된 수정안, 네트워크 실패, 앱 재시작과 원자적 저장을 포함한다. 중요한 알림의 잘못된 숨김과 비용·지연도 분리 측정한다. 단계 하나를 줄이는 설계 판단이며 비용/정확도가 개선됐다는 실측 결과는 아직 없다.

## 현재와 전환 범위

현재 설치 앱에는 기존 JevEngine.compile 및 문장 묶음 구조가 남아 있다. 이번 작업은 개발 기준 변경이며 앱 코드·활성 기준·설치를 변경하지 않았다. 기존 37개 단위/2개 실기기 통과를 새 구조 검증으로 주장하지 않는다.

후속 구현에서 OpenAI 정책 출력 계약과 앱 validator를 추가하고, 활성화·항목 변경의 Jev compile 경로를 제거한다. 기존 정책은 원문과 적용 상태를 보존한 이관/검증 후 전환한다. Jev는 검증·확인된 활성 JSON을 입력받아 일치 판단만 반환하게 한다. 모델·키는 이번 결정으로 바꾸지 않는다. Phase 상태와 [정책 모델 A~F](POLICY_MODEL_SETTINGS_SCOPE.md)의 완료 게이트는 유지하되 E의 생성 주체를 OpenAI로 변경한다.

세부 저장 전 검증은 [Policy JSON Validation](POLICY_JSON_VALIDATION.md)을 따른다. 추가 의미 검증은 위험 기반으로 실행하고 결정론적 오류를 LLM 판정으로 덮어쓰지 않는다.
