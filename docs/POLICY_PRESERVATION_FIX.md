# 기존 기준 보존 검증과 구조화 표시 개선 — 2026-09-24

## 변경

- 편집과 의미 검증이 같은 해석 계약을 사용한다. 실행기의 조건 설명을 공통 함수로 추출해 두 AI에도 전달한다. 예를 들어 SECURITY에 이미 로그인/인증이 포함돼 있음을 이름으로 추측하지 않게 한다. 전체 대화/선택 항목을 읽고 예시와 범위 축소 지시를 구별한다. 허용된 넓은 규칙이 기존 좁은 규칙의 행동을 포함할 때 항목 이름의 부재만으로 누락으로 처리하지 않는다.
- System UI 수집 제외, OS 알림 제어, 전체 앱 숨김을 구분한다. 지원하지 않는 OS 제어 부분만 제외하는 답변으로 독립적인 약속·미팅 예외나 앱별 광고 제외까지 삭제하지 않는다.
- 약속/미팅 관련 공지를 확정·일정 변경으로 축소하지 않는다. 숨김과 만나는 명시적 허용은 해당 부모의 SHOW 예외로 보존하고, 같은 범위 SHOW/HIDE의 미해결 충돌을 감추지 않는다.
- 의미 검증이 구체적인 오류를 반환하면 최대 한 번 보완한다. 원래 요청/이전 기준/거부된 제안/피드백으로 편집한 뒤 스키마·결정론적 검사와 독립 의미 검증을 다시 실행한다. 피드백을 새 사용자 권한으로 취급하지 않으며 확인이 필요한 경우 바로 질문한다. 무제한 재시도나 자동 적용은 없다.
- 검증을 통과하지 못한 변경은 보류 상태와 미적용 구조화 제안으로 표시하고, 상세 사유는 펼쳐 볼 수 있다. 다시 정리는 기존 사용자 답변을 보존한다.
- 기준 설명을 대상·개별 조건·ANY/ALL·처리·개별 예외와 부정·시간으로 구분한다. 기존 형식은 항목별로 현재 적용 중임을 표시하고, 변경안과 구분한다. 체크·수정·삭제는 검증된 새 형식 적용 후 제공된다.

## 검증 한계

공통 계약은 의미 해석의 정확도를 보장하지 않는다. 위험한 변경에 대한 검증과 사용자 확인은 유지한다. 기존 활성 기준은 임의 변환하지 않는다. 원본 실패 요청과 같은 계열의 합성 회귀, 단위 검사, 실기기 확인 결과는 결과 파일에 별도로 기록한다. 전체 품질 게이트와 AI Watch 구현 상태는 변경하지 않는다.

## 개발 중 확인한 실패와 구분

초기 회귀에서는 넓은 미팅 예외가 복원됐지만 단체방 잡담이 모든 잡담으로 넓어지는 응답도 발견했다. 대상 대화가 정해지지 않은 단체방 제한은 별도 재질문 검사로 분리했다. 예외 보존 양성 사례는 대상이 명확한 광고/뉴스 조건을 사용한다. 이를 원래 모든 요청이 한 번에 통과한 것으로 기록하지 않는다.

‘보안’ 타입에 로그인이 포함되는지 다시 묻는 불필요한 질문에는 공통 실행 조건 정의를 제공했다. 반면 보안 표시와 광고 숨김이 겹칠 때의 우선순위 질문은 실제 선택이 필요하므로 유지했다. 합성 UI 검사는 이 질문이 나오면 표시 우선이라는 합성 사용자 답변을 제출한 뒤 검증을 계속한다. 실제 사용자 요청에는 답변을 대신 입력하지 않는다.

화면 검사에서 구조화 항목의 접근성 식별 실패를 발견해 개별 표시 텍스트를 검사 대상으로 지정했다. 작은 제목 검사와 화면 켜기 처리를 보완하고, 빠른 좌표 스와이프 대신 낮은 속도의 컨테이너 스크롤을 사용한 UI 전용 검사가 통과했다. FLAG_SECURE는 유지한다. 빌드 산출물 파일 기록이 지연돼 동일 소스를 임시 폴더에서 빌드했다. 중간 테스트 결과 파일 기록 실패 및 실제 API/화면 실패 기록도 보존한다.

## 최종 결과

단위 57개, debug/test APK 빌드·lint 통과. Galaxy S23에 최종 debug APK 설치. 구조화 항목 표시 → 사용자 확인 → 저장 UI 전용 검사는 합성 fixture로 통과했다. 단체방 대상 재질문은 실제 API로 통과했다. 실제 API의 예외 보존/의미 검증 통과는 관찰됐으나, 해당 API+UI 결합 검사는 중간 자동화 실패가 있어 단일 실행 전체 통과로 기록하지 않는다. 사용자 저장 요청의 재검증은 통과했고 기존 활성 정책/답변을 보존한 채 7개 미적용 기준과 대화방 선택 질문을 남겼다. 사용자의 답이나 적용 승인을 대신 입력하지 않았다.
