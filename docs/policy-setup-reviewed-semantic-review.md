# 원문 대조 검사 추가 후 다회차 의미 검토

검토일: 2026-09-23. `policy_setup_reliable.py`를 사용하는 다회차 회귀 실행을 별도 에이전트가 원문·고정 답변·실제 턴과 비교한다. 분류 점수는 보지 않고 데이터·코드·프롬프트는 수정하지 않는다.

이 10개는 이전 실행에서 실패 내용을 이미 확인하고 개선에 사용한 **노출된 회귀 자료**다. 통과하더라도 독립 봉인 성능이나 새로운 사용자 요구에 대한 일반화 성능으로 해석하지 않는다. 생성 모델과 추가 원문 대조 모델은 같은 모델이므로 추가 호출 자체가 독립 검증을 뜻하지 않는다.

## 이번에 확인하는 변경

- 명확한 첫 지시는 원문을 보존하고, 기존 조건/답변을 병합하는 ready 초안은 설정용 모델이 원문과 한 번 더 대조한다.
- 앱 코드가 미활성 상태의 안내문을 고정해 ‘설정 완료’나 미지원 대안 기능의 약속을 막는다. 다만 질문·선택지·unresolved·최종 지시의 의미까지 코드가 보증하는 것은 아니다.
- 실제 후보 ID가 있는 conversation 질문은 field를 scope로 정규화한다. 모델의 목표 이해를 대신하는 것이 아니라 동일 UI 요소의 필드 계약을 고정한 것이다.

### 집중 확인: 기존 조건과 선택 대상

mt-008 최종 원문:

> Notify only about Gmail messages explicitly saying my bill is overdue, and YouTube new video uploads from River Workshop. Exclude YouTube live streams and comment replies.

수정하지 말라고 한 Gmail 부분이 원래 문장과 동일하게 남았다. Cedar→River만 바뀌었고 YouTube 예외는 유지됐다. 키워드 검사만으로는 알 수 없는 이 부분을 원문과 직접 비교했다.

mt-009 최종 원문:

> Google Calendar에서 시작 시간이 변경됐다는 알림을 알려준다. WhatsApp에서 유나가 보낸 메시지는 모두 알림을 받는다.

Calendar 기존 문장을 유지하고 사용자가 선택한 유나 알림 방향을 반영했다. ‘유나가 아닌데 표시만 유나’라는 v5의 새 구분은 남지 않았다.

mt-006/007은 표시 이름뿐 아니라 저장된 실제 선택 ID가 최종 referenced_candidate_ids에 남았고, 다른 후보 또는 전체 WhatsApp으로 범위를 넓히지 않았다.

## 남은 결함과 한계

1. **미지원 선택지가 여전히 나올 수 있다.** mt-003 첫 질문의 `Messages with attachments`는 현재 제공 필드로 첨부 존재를 판정할 수 있다는 보장이 없다. ‘알림 텍스트에 첨부가 명시된 경우’로 제한하지도 않았다. 이번 사용자는 그 옵션 대신 미납 조건을 직접 답해 최종 정책에는 유입되지 않았지만, 다른 선택 분기에서 막힐 수 있다. 고정 message만으로 질문·선택지의 기능 정합성을 해결한 것은 아니다.
2. **출력 언어 준수는 안정화되지 않았다.** mt-007은 영어 요청·답변 없는 대화 선택 흐름인데 최종 정리문이 한국어다. 이번 의미 검토에서 조건 손실은 발견하지 못했지만 사용자 언어 UX와 자동 문자열 평가는 실패한다.
3. **추가 검사는 동일 모델의 1회 재검토다.** 앞선 오류를 고쳤다는 회귀 증거는 있지만 모델 간 독립 합의나 통계적 무오류 보장이 아니다. 언어 오류나 선택지 오류처럼 검토 범위 밖 문제는 계속 남을 수 있다.
4. **분류·컴파일·실앱은 별개다.** 여기서 좋은 최종 지시를 얻어도 Jev 정책 JSON 변환과 알림 분류, Galaxy 표시가 검증된 것은 아니다. 이번 검토는 해당 결과를 읽지 않았으며 결론을 확대하지 않는다.

최종 9개 ready 지시와 1개 unsupported 상태에서 이전에 지적한 수신자 관계, 기존 Gmail/Calendar 조건, 선택 방 범위의 중대한 손실은 이번 출력에서 발견하지 못했다. 다만 질문 과정의 첨부 선택지와 출력 언어 문제를 남은 결함으로 기록하며, 전체 기능 통과나 출시 가능 판정을 내리지 않는다.
