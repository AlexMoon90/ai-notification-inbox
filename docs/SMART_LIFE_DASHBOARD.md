# 스마트함 구조화 대시보드

2026-10-05 사용자 지시서의 우선순위에 따른 네이티브 Android 구현.

## 화면

- 최근 업데이트 → 돈 큰 카드 → 쇼핑·배송/일정·약속 두 열 → 실제 정보가 쌓인 선택 카테고리.
- 돈: 계좌 입출금 / 거래 내역 / 내야 할 돈 / 통계. 상위 메뉴는 밑줄 탭과 좌우 HorizontalPager로 연결하고 기간·종류는 둥근 필터로 구분한다. 부분 계좌번호와 금융기관을 함께 표시하고 계좌별로 필터링한다.
- 거래금액과 잔액은 별도 필드. 잔액은 상세에만 표시한다.
- 사용자 후속 요청에 따라 상세에 원문과 관련 문맥을 자동으로 보여주며, `원본 앱에서 보기`로 원래 앱을 연다. 메인/카테고리 목록은 구조화 정보를 유지한다.
- 정기결제는 payment + recurring 속성. 납부 전 정보와 완료 거래를 분리한다.
- 명시적인 청구번호·금융기관·금액 일치와 모순 없는 계좌만 납부 완료 연결에 사용한다. 후보가 여러 개면 연결하지 않는다.
- 사용자가 납부·일정 상태를 수정할 수 있다. 변경 이후에는 다시 변경 배지를 표시한다.
- 배송/예약의 현재 상태는 동일 기관·종류·참조번호로 묶고 상세에서 이전 원문을 확인한다.

## 추출 범위와 안전한 기본값

기존 금융 직접 파서, 금액/잔액 후보 검증, 대화 문맥 게이트, 새 금융 패턴의 OpenAI 템플릿/반복 Jev 판단/일일 예산을 유지한다. 이번 구현은 외부 과거 메시지 일괄 재분석을 실행하지 않는다.

새 로컬 구조화는 라벨이 명시된 청구서, 배송의 상품명/주문번호, 예약일시/예약번호를 지원한다. 쿠팡 소비자 앱의 명시적인 배송 출발/완료는 별도 상품명 라벨이 없어도 상태를 표시하며, 이 경우 상품명을 만들어 내지 않는다. 임의 문구의 모든 쇼핑앱을 지원한다는 뜻은 아니다. 원문은 보존하되 구조화 근거가 부족한 일반 알림을 스마트함의 빈 카드로 올리지 않는다.

대화형 납부 요청은 기존 문맥 판단이 돈으로 판정하고 현재 메시지의 금액이 선택된 경우에만 명시적인 입금/송금 요청을 `payment_request/pending`으로 올린다. 확인 필요 문맥 표시는 유지한다. 사람의 "보냈어요"만으로 송금 완료를 만들지 않는다.

일정은 원문 일시 표현을 보존한다. 연도/시간이 없는 표현을 임의의 시각으로 확정하지 않는다. 완전한 납부 날짜는 그날 말까지의 기한으로 처리한다.

투자/건강/업무는 구조화된 기록이 3개 이상일 때 표시한다. 현재 투자 파서는 명시적 종목/체결/가격 알림, 건강은 지원 건강앱의 걸음 수에 한정한다. 학교·고객·프로젝트의 명시적 라벨이 반복되면 사용자가 `따로 묶기`로 수락한다. 임의의 새 개인화 스키마를 LLM이 자동 생성하는 기능은 추가하지 않았다.

통계는 저장된 확정 거래 기준이다. 계좌 출금/송금을 결제 지출에 더하지 않는다. 지출 분야는 검증된 분류 근거가 아직 없으므로 만들어 표시하지 않는다. 실제 금융 명세서와 합계가 같다는 보장은 없으며 중복 알림의 완전한 통합은 별도 범위다.

## 데이터 변경

Room 9 → 10: MoneyEvent의 recurring/status/dueAt/referenceKey/settledByTransactionEventId/spendCategory 추가, LifeEvent 추가. 기존 원문과 문맥은 유지한다. 모든 원문을 한 번에 메모리에 올리지 않는 16건 단위 로컬 보완 테스트를 제공한다.

## 검증

단위: 기존 금융/문맥/DB 마이그레이션 회귀, 통계에서 출금·잔액·청구 제외, 명시적 청구/배송/일정, 상태 묶음, 납부 연결의 계좌·참조번호·중복·역순 도착, 대화형 요청 게이트.

실기기: `SmartLifeDashboardDeviceTest`는 합성 데이터로 네 메뉴, 필터, 선택 카테고리 비노출, 상세 원문 토글을 검증한다. `SmartLifeBackfillDeviceTest`는 기존 데이터의 로컬 필드 보완만 수행하며 외부 AI 호출을 하지 않는다.

최종 확인: 단위 테스트 210개, Galaxy S23 합성 UI 테스트 및 로컬 데이터 보완 테스트 통과. 기기 잠금 때문에 실제 데이터 화면의 시각 확인은 하지 않았으며 합성 컴포넌트 화면을 참고 보드와 비교했다. 상세 시각 기록은 루트 `design-qa.md`에 있다.

## 후속 UX 변경

돈 메인 카드는 제목/주간 결제액을 한 줄로 묶고 바로가기를 텍스트형으로 압축했다. 거래 두 개의 상대방·금액·기관/계좌는 유지하고 중복 더보기 행을 제거했다.

목록에 실제 표시된 이벤트는 `(sourceNotificationId, updatedAt)` 기준으로 자동 확인 처리한다. 대시보드 미리보기, 통계, 옆 페이지 사전 구성, 화면 밖 기록은 자동 확인하지 않는다. 상세를 직접 연 경우에도 해당 이벤트를 확인 처리한다. 새 변경은 다시 미확인으로 나타난다. 업데이트 목록은 진입 시 항목을 고정해 읽음 처리 직후 행이 사라지지 않는다.

수동 확인 버튼과 원문 펼치기 버튼은 제거했다. 상세의 원문/관련 증거는 기기 저장소에서 자동으로 읽어 같은 화면에 표시한다. 원래 앱 열기는 별도의 버튼으로 유지한다. 이 변경은 이전 '원문 토글' 기준을 대체하는 사용자 지시에 따른다.

### 체크카드 결제 확인

삼성 월렛의 완료 결제와 동일 금액의 완료 계좌 출금이 2분 이내이며 양쪽에서 후보가 하나씩인 경우 돈 목록에 확인 질문을 표시한다. 시간·금액 일치만으로 자동 확정하지 않고, 사용자가 처음 체크카드라고 확인하면 월렛 패키지·금융기관·표시된 부분 계좌번호 조합을 로컬에 기억한다. 같은 조합의 기존/새 거래는 두 알림이 모두 동일한 후보 조건을 만족할 때 다시 묻지 않고 체크카드로 연결한다. 다른 계좌/기관은 별도 확인하며 계좌 식별정보가 없으면 거래 단위로만 확인한다. 가려진 계좌번호를 복원하거나 서로 다른 마스킹을 같은 계좌로 추측하지 않는다.

확인된 결제는 체크카드 사용액에 한 번만 포함하며 출금 기록과 양쪽 원문은 유지한다. 거래별 다른 거래 선택은 계좌 규칙보다 우선하며 신용카드 확정으로 해석하지 않는다. 상세의 다시 확인은 해당 계좌 규칙과 같은 계좌의 긍정 확인 결과를 해제한다. 질문을 나중에 확인하도록 미루면 같은 계좌 후보도 현재 화면 세션 동안 함께 미룬다. 명시적인 신용카드, 금액/시간 불일치, 복수 후보에는 자동 연결하지 않는다. 기존 거래별 긍정 확인도 계좌 식별정보가 있으면 기억된 기준으로 전환하며 외부 AI 호출은 없다.

### 카드 승인 알림 설정 안내

최근 30일 내 완료 출금 중 결제수단이 없고 같은 금액·2분 이내 결제 기록도 없는 경우, 돈 화면을 열면 카드 승인 문자/앱 알림 설정 안내를 한 번 제공한다. 상대방이 사람인지 상호인지 추정하지 않으며 출금을 체크카드로 재분류하지 않는다. 새 알림의 짝이 들어올 시간을 위해 수신 직후 2분은 안내 대상에서 제외한다.

안내에서는 계좌 입출금 알림과 카드 이용·결제 승인 알림의 차이, 은행/카드사 앱 또는 고객센터의 신청·설정, 이미 설정한 사용자의 알림 및 접근 권한 확인을 설명한다. 확인하거나 닫으면 반복 표시하지 않고 계좌 입출금/거래 내역의 ‘체크카드 결제 알림 설정 안내’ 버튼으로 다시 읽을 수 있다. 외부 신청을 자동 실행하지 않는다.

### 월렛·체크카드 승인·계좌 출금의 한 거래 표시

체크카드로 명시된 완료 승인과 삼성 월렛 결제가 동일 금액·2분 이내·동일 가맹점이고 양방향 후보가 유일하면 카드 승인을 대표로 묶는다. 양쪽에 카드 식별정보가 있으면 충돌하지 않아야 한다. 동일 금액의 신용카드 승인도 경쟁 후보로 고려해 체크카드만 선택하는 오결합을 막는다.

출금은 기존에 사용자가 확인한 월렛/계좌 연결 또는 같은 금액·시간·상대방의 유일한 출금 근거로 연결한다. 복수 계좌 후보, 기존 연결 계좌와 충돌, 사용자가 다른 거래라고 답한 출금은 자동으로 추가하지 않는다. 본문에서 가맹점이 확인되지 않으면 금액·시간만으로 두 결제 승인을 합치지 않는다.

대시보드/거래 목록/결제수단 통계에서는 한 결제로 표시하고 원본 저장 데이터는 유지한다. 계좌 입출금은 별도 계좌 현금 흐름으로 보존하며 결제 지출에 더하지 않는다. 상세는 대표 승인 및 월렛·출금의 원문을 함께 제공한다. 투영은 수신 순서에 의존하지 않으며 뒤늦게 승인 알림이 추가돼도 다시 계산한다.
