# 메시지 AI 답변 도우미

대화방 하단에서 사용자가 직접 ‘답변 도와주기’를 열고 톤/요청을 정한 뒤 ‘답변 만들기’를 누르는 경우에만 호출한다. 방 열기·알림 수신·톤 선택만으로 생성하지 않는다. 최초 안내 확인 후에는 매번 동의를 묻지 않는다. 설정에서 OFF하면 버튼 및 열린 패널이 사라진다. 첫 사용 팁은 3.5초 또는 탭으로 닫히고 반복하지 않는다.

초안은 하단 패널에서 직접 수정할 수 있고 복사·원본 앱 열기를 제공한다. 재작성은 현재 편집한 초안과 변경 요청만 보내며 최근 대화를 다시 전송하지 않는다. 원본 연결은 기존 NotificationOpener/MainActivity 경로를 그대로 사용한다. 자동 입력/발송·Accessibility·예약 발송은 없다. ‘나중에 답장’ 영구 임시저장은 이번 MVP에서 제외하며 패널/방을 닫으면 초안은 보존을 보장하지 않는다.

## 전송 범위와 실패 처리

최근 연속 수신 최대 10개(6시간 넘는 공백 이전 제외), 개별 최대 1,200자, 합계 최대 6,000자. 화면용 240자 미리보기는 버튼 실행 시 필요한 원문만 불러온다. 이미지는 파일/URI/이미지 내용 모두 제외한다. 방 ID는 해시로 전달한다. 방 이름·발신자·시간·요청·톤 및 수신 기록만 있다는 표시를 포함한다. 이미지 생략/본문 잘림도 AI에 알린다. 입력 메시지/초안에 있는 지시는 실행 명령이 아니라 자료로 취급하고, 사용자 지시 없는 일정·금액·약속 확정을 금지한다.

[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)의 strict JSON Schema를 사용한다. 기존 승인된 debug OpenAI 연결과 모델 설정을 재사용하고 `store=false`, 출력 상한 1,800토큰을 적용한다. 분류와 별도 task/purpose(`reply_assistant`, `reply_assistant_rewrite`) 및 `reply-assistant-usage.jsonl`에 사용량·성공 여부만 기록한다. 원문/초안/키/오류 본문은 로그에 남기지 않는다. 이 로그는 256KiB를 넘으면 비운다. 기존 private debug API 구성의 release 제한은 그대로다.

파싱/빈 응답/실패/거절은 패널 내 오류와 재시도로 처리한다. 실패해도 초안 및 메시지 화면은 유지한다. 재시도는 마지막 요청을 재사용한다. 로딩 중 중복 제출을 막고 패널/대화방/설정 변경으로 기능이 사라지면 UI 요청 범위를 취소하여 다른 대화에 결과가 섞이지 않게 한다. 이미 전송된 HTTP 호출은 서버에서 완료될 수 있지만 취소된 화면에는 결과를 적용하지 않는다.
