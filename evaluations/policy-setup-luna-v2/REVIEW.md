# Luna low 개선 검증 — 2026-09-23

## 변경

`policy_setup_luna_v2.py`는 기존 검토 클라이언트를 재사용하며 두 차례 호출 모두에 관찰 정보 계약을 추가한다. 현재 후보 수와 선택 여부는 코드가 입력에서 계산한다. 후보가 없는 경우 waiting, 후보가 있으나 선택이 필요한 경우 needs_input의 차이를 명시했다. 후보의 이름/미리보기로 사용자의 방을 자동 확정하지 않는다. 후보 유무만으로 앱 전체 조건이나 미지원 요구를 방 선택으로 바꾸지 않도록 명시했다.

충돌 질문도 관찰 가능한 발신자 표시 이름을 사용하도록 제한하고, 아직 고르지 않은 조건에 대한 이름·채널 후속 질문을 앞당기지 않도록 했다. 모델은 gpt-5.6-luna, reasoning low 그대로이며 기존 파일/결과와 GPT-4.1 기본 진입점은 보존한다. 코드가 상태를 강제로 통과시키거나 정답 질문을 삽입하는 방식은 사용하지 않았다. 따라서 이는 모델 출력 개선이지 논리적 정확성 보장은 아니다.

## 검증 설계

기존 설정40개와 다회차10개를 회귀검사로 실행한다. 새 사례8개는 API 호출 전에 작성하고 manifest에 고정했다: 한국어·영어 후보 선택2, 발신자 충돌2, 후보가 있어도 앱 전체 범위 유지2, 후보가 있어도 미지원 조건 거부2. 같은 작업자가 작성한 작은 합성 표본이며 독립 블라인드 평가로 부르지 않는다. 정답 상태·선택 ID·사전 답변은 평가기에만 두며, 선택/답변 단계 전에는 모델 입력에 전달하지 않는다.

로컬 테스트49개 통과. 신규2개는 후보 갱신이 요청 입력에 반영되는지, 선택을 만들어내지 않는지, 원문 대조 호출에도 같은 모델·계약이 적용되는지 확인한다. 정확도는 별도 실제 API 결과와 원문 검토로 평가한다.

이번 작업은 Phase 0 미완료 상태에서 사용자 요청으로 진행하는 독립 AI 설정 실험이다. Jev 반복 분류, 실행 정책 JSON, Android 앱·실기기 검증을 대신하지 않는다.

## 원문 검토

- mt-007: 후보가 없을 때 waiting, 도착 후 실제 ID/label 선택지, 선택 후 Project Orbit ID 유지 및 답변 요청 조건 보존을3회 확인했다.
- mt-009: 질문에 ‘실제 발신자’ 확인을 추가하지 않았다. 관찰된 이름에 대해 허용/제외를 선택했고 기존 Google Calendar 문장을 원문 그대로 유지했다. 일부 최종 지시에는 폐기한 제외 조건을 ‘적용하지 않는다’는 중복 문장이 남는다. 의미가 뒤집힌 것은 아니지만 후속 Jev에서 중첩 부정을 오해하지 않는지는 미검증이다.
- mt-008: Gmail 조건·YouTube 새 업로드 한정·라이브/댓글 제외는 유지하면서 채널 이름만 바뀌었다.
- mt-001~006: 제공한 이름, 경기 종료 및 승패, 연체 청구서와 영수증/광고 제외, 알림 본문 채널명 한정, 오늘 승인, 선택한 방을 유지했다.
- pilot-039: 아직 선택하지 않은 사람·채널 이름을 미리 묻던 후속 질문이 사라졌다.
- fresh-01~04: 선택한 방 ID, Slack 표시 이름 허용, Teams 표시 이름 제외 및 Gmail 조건 유지 확인. fresh-01의 최종 초안에는 의미로 해석하라는 구현 관련 표현이 추가돼 사용자 표시 문장은 더 다듬을 여지가 있다.
- fresh-05~08: 후보가 존재해도 전체 앱 지시는 방 선택을 요구하지 않고, 숨겨진 참여자/읽음 상태는 지원 불가로 유지했다.

검토는 같은 주 작업자가 결과 원문을 읽어 수행했다. 자동 점수는 상태·필수 어휘·후보 참조 검사이며, 전체 의미 정확도100%로 읽으면 안 된다. 신규8개는 이번 출력에 노출되기 전에 작성했으나 독립 작성/대규모 모집단 평가가 아니다. 반복3회도 장기 안정성 보장은 아니다.
